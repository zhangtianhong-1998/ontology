# 路线3：需求与用户故事

本文中的代码、配置路径及命令均以仓库的 `route3/` 目录为基准；文档链接可直接点击。

本文中的对象、字段、公式和地区等均为假设性例子，不说明真实输入包含这些内容。运行时先检测证据和适用性；没有相应内容就不启用该提取器。目标模型的五类根也不要求输入覆盖全部类别。

## 1. 范围与新增价值

输入为路线2的本体、来源快照、记录候选、证据和局部对象，以及需要应用映射的同结构或可适配新数据。先冻结 `ontology_version`，再生成规则、批量映射、核查融合。三种输出明确分开：

- 类型与关系定义：固定版本，当前映射运行不修改。
- 源记录与内部对象之间的映射：可按条件作用于很多记录。
- 身份归一与断言融合：保留原始对象 ID、条件和证据，可追溯和失效。

若出现现有本体无法表达的新类型或新关系，保存扩展候选，进入下一次独立构建，不在当前映射过程中悄悄改变目标。本路线不要求人工批准这一过程。

## 2. 用户故事及验收

| ID | 用户故事 | 验收条件 |
|---|---|---|
| R3-US01 | 作为实验者，我希望映射结果对应一个明确本体版本 | 所有规则和输出含 ontology_version；运行中目标类型哈希不变 |
| R3-US02 | 作为开发者，我希望将发现的规律复用于后续记录 | 生成受限 MappingRule，明确 selector、键、引用绑定、条件和证据要求；新记录由程序执行 |
| R3-US03 | 作为模型使用者，我希望同一对象跨表出现时正确对应 | 身份与概念相似分开；同名异义不合并；来源 ID 不被删除；C08/C09/C13 满足 |
| R3-US04 | 作为业务使用者，我希望融合后仍保留限制范围 | 条件不同、口径不同或版本不同的边不合并；C12 满足；反证和冲突仍可查询 |

## 3. 接受要求

- 映射候选必须有可执行的选择条件；基于几个样本学到的模式默认只在已经验证的作用域内复用。
- 每次执行均检查字段存在性、键完整性、引用歧义和条件。命中映射不代表结果自动正确，仍通过共同校验。
- 分别维护“同一类型”“同一业务概念”“同一对象身份”“引用某定义”；不能将它们统一为字符串去重。
- 不默认全局一对一映射。指标可依赖多个度量，一个维度可被多个 API 使用。
- SAND、图匹配或 LLM 的候选分数不直接触发对象身份合并。
- 接受策略、预算及条件规则均有版本。更新一个策略不能覆盖过去结果，应生成新的运行产物。

## 4. 暂不建设

不开发映射编辑 UI、在线查询网关、生产发布、复杂规则学习平台、OWL 导出等附加功能。原型提供 CLI 和可读 YAML，通过两个业务案例及规模实验验证执行能力。
