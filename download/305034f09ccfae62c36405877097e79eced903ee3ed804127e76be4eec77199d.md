# V13：类定义、关系路径、实例绑定与画布修复

本轮依据 V12 的产物和同一份模拟输入定位问题。保留原有 23 张表、1,102,238 行数据和全部旧结果，不通过修改数据迎合抽取逻辑。代码以简洁原型为目标，复用现有索引、证据合同及执行阶段。

## 需求与实现

1. **画布：连线在下，节点在上。** SVG 分为连线、关系文字、节点三层。连线可以穿过其他节点的位置，由不透明圆形节点遮挡；取消绕节点的网格寻路。平行边及反向边分开，关系文字沿线寻找不与节点、节点文字、其他关系文字重叠的位置。实在无法放下的文字暂时隐藏，悬停仍可查看，避免用大块标签遮住节点。拖动、缩放、自动排布和适配视野继续保留。
2. **没有既有模板时，也能补充类定义见证。** 冷启动未决记录可以从当前索引中召回同表、同类声明、相容身份与范围的记录。单条记录中的明确类定义也可以支持新类；只有从实例变化中推导通配槽位才要求多条见证。疑似类声明仅用于召回，完整来源仍须通过编译校验。
3. **不同定义不再因报错相同而混成一个修复任务。** 修复分组纳入定义身份；完整记录受组包上限约束。追加见证超限时明确报告，不裁切原始证据冒充完整记录。
4. **分类属性与业务范围分开。** 来源元数据明确声明为分类或类别的字段保留为 `classification_attributes`，参与类型身份、等价与泛化校验。其完整值和来源证据保留，但不作为事实的业务筛选条件。租户、版本、命名空间和计算参数不能借此移除；没有独立分类声明时不猜测。类型详情也显示分类属性。
5. **配置关系校验与辅助表路径。** 同一配置记录不能把自身当成两端；关系文本须与所用引用字段相对应。已接受的记录关联可以作为有界探索入口，经来源声明的引用查找两端业务定义。支持明确的未限定表名的字段引用及条件分支，但仍要求唯一目标、有效选择条件和当前快照精确校验。候选生成、关系编译和实例化均重放路径。技术匹配及单边路径不会自动成为业务谓词。
6. **事实字段召回使用有来源的参数名和别名。** 候选召回与最终校验共用同一组源名称，优先完整名称命中，避免有限候选名额被较弱匹配占满。单位支持“出口量，吨”等明确声明及同尺度别名；不同尺度单位不自动换算或合并。单位在抽取、等价与泛化阶段也保留大小写，避免把 MW 与 mW 当作同一单位。范围字段仍须来自事实来源，不能凭模型填写不存在的列或常量。
7. **控制无效修复和请求膨胀。** 模型请求不再重复携带整组调度编号，改为数量与摘要；本地完整调度清单和完整来源记录保留。相同证据因输入超限失败后，不因无关类型增加而重复提交；证据或输入上限改变后可重试。失败不得标为收敛。短编号还原失败时保存结构化响应以便诊断，仍拒绝无法核验的证据引用。
8. **覆盖率口径明确。** 模板覆盖率仅描述模板来源表，不能代替全部定义记录或全部输入覆盖。新报告按索引中的定义来源记录核对绑定，并单列未进入模板范围的表；无模板但已有精确绑定的记录不算失败。

## 源结果回放与边界

以下检查不调用真实 LLM，也不改写 V12 产物。

- V12 五个维度保存的十份原响应，经过分类属性修复后均通过概念编译；原模型提出的角色另行保留，不能据此声称模型判断全部正确。
- 九个 API 修复包经实际请求编码后为 43,429–44,881 字节，低于 100000 字节上限。九包均取得两条完整且相容的实例见证，未扩大 exact 对齐权限。这是这些修复包的测量结果，不代表全部组包都已验证不会超限。
- 全定义源统计在 V12 上读到 29,780 个唯一来源行，已有类型绑定 22,040 行，覆盖约 74.01%，而模板来源表内部的覆盖为 98.52%。其中 API 表 2,500 行全部未绑定。新报告保存为 `definition_source_coverage.yaml`；它仍只统计被索引识别为定义的记录，不代表 110 万行全部输入的语义正确率。
- 事实字段中，`sales_volume_ton`、`export_volume_ton`、`avg_price_cny_per_kg` 分别能召回“销量”“出口量”“均价”及匹配单位。它们是否能生成合格事实实例，还取决于来源范围等其他合同。
- 辅助表引用回放找到 7 条有来源声明的引用、16 条通向已绑定业务端点的路径，另有 7 条路径缺少终点类型绑定。旧结果中没有一组具备两端完整证据，因此完整关系候选仍为 0。本轮修复增加可用路径与缺口报告，不保证把所有孤立节点连接起来。
- `domain_code=FRUIT` 的源注释仅为一般业务字段说明。旧流程先把含 domain 的列作为 scope 候选，再接受模型的 applicability 判定，尚不足以证明它是事实适用条件；也没有足够证据直接改成分类或命名空间。新分类合同不会擅自移除它。这是事实绑定仍可能失败的重要未决项。
- 新路径仍受原始声明、目标唯一性和数据覆盖约束。任意无注释输入、多跳复杂转换、跨表同义名与真实业务范围的自动判定，不能由这些测试证明已解决。
