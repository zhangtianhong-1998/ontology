# V11 编号、关联与语义分组修复

## 已确认的问题

2026-09-30 10:09（北京时间）停止旧实验，退出码 143，保留了中断检查点。仍使用同一份 23 表、1,102,238 行的模拟输入，不通过修改数据降低实验难度。

旧 V11 把部分记录主键和引用编码接受为 `identity`。原有校验只证明模型引用的值确实存在，没有证明它是定义的命名空间、租户或版本。该角色参与模式指纹和模板不变字段，造成编号变化被误判为新语义。定义模式由 V10 的 880 增至 9,188，而定义卡数量基本不变；其中度量定义由 26 个模式变成 5,000 个，接口定义由 10 个变成 2,500 个。

另一处问题在关系排序：泛化的“引用”“关联”注释会提高任意同值目标的优先级。数字编号取值密集时，技术上能连接的候选过多，模型反复处理缺乏业务依据的连接。不同召回来源还可能把同一条完整规则重复送审。

## 处理原则与实现

1. **编号用于绑定，定义身份另行举证。** 记录主键、编码不能仅凭唯一性或模型解释成为 `identity`；明确的租户、命名空间、定义版本声明继续保留。缺注释时结合实际值和已有统计提出候选，证据不够保留 `unknown`。消费旧缓存候选时也重新检查这条边界。
2. **分组不按记录编号增长。** 引用值留在完整卡和回源索引中，不参与定义模式指纹；管理信息、来源信息也不制造新模式。公式、单位、适用范围、真实定义身份和未知语义内容仍参与区分。模式相同只影响调度，不能直接合并对象；完整模板契约通过后才能复用。
3. **发现关联与理解关系分开。** 程序用 distinct 倒排提出字段对，核验条件、作用域、匹配比例、重复目标和缺目标，再按来源字段及关联族分配有限的送审机会。同值只构成技术证据，不能自动成为业务关系。部分匹配、条件匹配和复合范围保留原有语义；尚未检查的范围继续报告未决。
4. **重复关系按完整证据去重。** 来源、目标、转换、选择条件、作用域、快照和核验结果都相同，才共享一次语义送审；保留各召回来源。只有数字重合的候选进入受限探索队列，不能仅凭泛化注释提到优先队列。
5. **请求使用可逆短编号。** `llm.prompt_reference_aliases: true` 默认启用。在请求发送边界替换系统记录、证据、类型等标识，以及独立引用字段中明确的不透明字符串编号；回包按来源位置还原，再进入现有编译和原文校验。可读类别、数值类型和完整语义内容保持原文。短码只在当前请求内有效。不同来源的相同原值不会自动共享短码；只有已核验的实际连接见证可以关联。
6. **结构化词义不再直接丢弃。** 有名称及结构化语义线索的记录可以进入有限候选队列，原始 JSON 继续作为待判断内容，不凭键名自行生成术语定义或引用关系。普通管理 JSON 不构成这类线索。

## 扫描、组包与调用的边界

这里限制的是语义枚举和模型调用，不是取消必要的数据读取。全输入统计、distinct 索引和批量关联核验仍可能读取百万行，但不为每行发起模型调用，也不枚举各字段值的笛卡尔积。已建立的模板用于直接绑定后续记录；未覆盖的定义、公式变化或关系端点才形成补充任务。

新请求不会丢弃完整公式、说明、范围与反证来缩短上下文。长文本或 JSON 内嵌编码如不能安全、可逆地替换，保留原文并在审计中记录；角色推断阶段仍需读取少量原始样本。短码是上下文表示，不是数据脱敏，也不会自动降低抽取次数。

`prompt_reference_audit.jsonl` 保存请求映射和实际发送内容；本地 `trace.jsonl` 保留原始证据与还原后的结果。审计文件不是可公开的脱敏材料。配置为 `false` 可关闭短码，不能以关闭校验替代还原。

## 验证方法

先用旧实验保存的 23 个列角色响应重新执行新校验，再对原输入重建语义卡索引。这一步只有程序计算，没有创建模型客户端，也不调用 API。执行方法：

```sh
cd route2
.venv/bin/python scripts/replay_role_preflight.py \
  --config config/runtime.full-v11.yaml \
  --trace <旧实验或归档>/trace.jsonl \
  --output local_config/v11-correction-preflight
```

脚本要求来源快照完全一致，缺少响应时失败。输出分表模式数、分组预算遗漏及回放次数；模式数不能当作下一次运行的实际调用数。关系候选、模板复用及模型语义准确性须另行验证。

运行回归覆盖：不同编号而语义相同、相同编号但命名空间不同、缺注释和异名列、部分命中、目标歧义、条件/复合规则、来源短码冲突与回包还原。

最终分组预检已完成：重放 23 个保存响应，扫描 1,102,238 行，耗时 341.773 秒，真实模型调用为 0。结果在本地 `route2/local_config/v11-correction-preflight-final/manifest.yaml`；这验证了新校验处理旧错误提议的行为，不代表新模型响应一定相同。

对旧的完整关联核验证据重新调度：规则队列从实际检查的 1,066 条变为 1,034 条，其中数字同值候选由 570 条变为 538 条。本次数据没有完整规则重复，精确去重命中为 0；主要改善来自定义身份修复，不能声称关系去重已经大幅压缩此数据集。该对照未重新发现候选或构建关系包，新实验仍需重新核验。

旧请求的短码回放覆盖 1,195 个请求、1,119 个已有返回，往返还原错误为 0。概念输入的 UTF-8 体积约减少 13%；这不是实测 token 节省，也不证明业务语义正确。

独立审查复现并关闭了业务参数字典误编码、条件字典还原、同名业务键误作表达式、未知短码残留等问题。完整模板、JSON/SSE 传输与缓存换源均有回归。条件和短码复用不能绕过已有来源校验。

最终完整回归：`route2/.venv/bin/python -m pytest -q`，**1,210 项通过，77.62 秒**。测试开始与结束的实现文件 SHA-256 一致，`git diff --check` 通过。本轮预检与回归没有调用真实模型；付费调用仅在重新启动实验后发生。

## 本轮仍未解决的范围

- 异名值匹配并不能解释所有企业自定义关联；未知多跳、列表、JSON 路径仍可能需要后续声明归纳。
- 来源缺少定义或业务口径时，框架会保留未决，不能保证补出正确本体。
- 相似度检索只召回候选；本轮不以更宽松的相似匹配制造可复用关系。
- 已有模板减少模型调用，但仍需程序回源核验；尚未实现通用的跨快照零扫描增量机制。
- DataHub 继续是本地元数据标识、图适配和导出契约，不负责自动发现业务关系。没有运行 DataHub 服务器或向其上传数据。
- 原有静态领域知识、周期编排 Agent、复杂配置语义及跨领域业务 Gold 待办保持不变。工程回归和模拟实验不等于真实企业语义验收。
