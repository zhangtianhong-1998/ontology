# 路线3：软件详细设计

本文中的对象、字段、公式和地区等均为假设性例子，不说明真实输入包含这些内容。运行时先检测证据和适用性；没有相应内容就不启用该提取器。目标模型的五类根也不要求输入覆盖全部类别。

## 1. 两阶段运行

阶段 A 调用或读取路线2，保存本体定义及接受策略版本。阶段 B 固定这些定义，生成/应用映射，融合对象与断言。

```text
路线2运行产物
  → 冻结 ontology + acceptance policy + source snapshot
  → 提取条件映射候选
  → 验证规则、留出检查
  → 本地索引召回 + 可选语义匹配插件
  → 程序批量执行、逐记录条件/身份检查
  → 保守身份归一、相同断言证据合并、冲突保存
  → 映射 YAML、对象/关系分片、canonical 映射、评测
```

冻结对象类型、关系类型和约束，**不禁止在已有类型下产生新的实例对象**。新对象缺少跨表身份依据时保留源局部 ID；遇到无法表达的类型或关系时，输出 `ontology_gap` 及下一版本扩展候选。

原型允许以文件哈希作为版本，不需要搭建版本管理服务。路线3结果指向父运行 ID，不能只复制旧结果后修改 manifest 冒充新执行。

## 2. 模块与接口

| 模块 | 接口草案 | 责任 |
|---|---|---|
| `r3/mapping.py` | `propose_rules(r2_run) -> list[MappingRule]`、`validate_rule()` | 将有证据的抽取计划变成条件映射；编译和静态检查 |
| `r3/execute.py` | `apply_rules(rules, batches, ontology) -> AssertionIterator` | 复用路线2的查找/解析；批量执行及逐记录守卫 |
| `r3/fusion.py` | `resolve_identities()`、`merge_assertions()` | 区分身份与相似；保留条件、反证和来源 |
| `r3/incremental.py` | `affected_items(change, dependency_index)` | 来源、规则与本体变化引起的失效和重算 |
| `r3/sand_adapter.py` | `suggest_candidates(snapshot, bounded_rows)` | 可选，转换到 SAND 的真实扩展接口并回收候选 |
| `r3/pipeline.py` | `map(config) -> RunManifest` | 冻结、执行顺序、预算、结果和实验入口 |

不要重新实现路线2的公式解析、候选索引和 MCP Agent。映射阶段默认复用冻结证据，不再次检索企业资料；若额外检索作为实验开关启用，创建新的证据快照并计入成本，不能仍标为同一 E3 对照。

## 3. 条件映射 DSL

一条 `MappingRule` 包含：

| 字段 | 含义 |
|---|---|
| id、version、ontology_version | 规则身份和固定目标版本 |
| source_table、required_columns | 输入表与必要字段；缺字段即本规则无法执行 |
| selector | 哪些记录可用，使用共同条件 DSL |
| subject | 主体类型、键字段、命名空间与身份范围 |
| operation | 初版仅支持引用查找、公式绑定、维度成员规则、字面值属性 |
| target | 目标类型、表或对象索引、作用域字段绑定、单/多目标要求 |
| predicate、attribute | 根/派生关系；数据关系使用 attribute |
| scope、condition | 输出断言的业务范围与条件；不得仅有 selector 而丢失输出范围 |
| evidence_policy | 必需来源字段、公式区间、已接受定义或文档引用 |
| generalization | 规则已验证适用范围、样本/留出统计、未验证区域 |

参考[完整合成规则](config/mapping.example.yaml)。规则只使用已有字段和固定操作；禁止可执行字符串或任意网络调用。`selector` 解决哪些源记录需要处理，`condition` 解决输出关系在什么条件下成立，二者不自动相等。

### 3.1 规则生成

先把路线2成功执行的明确引用/解析计划提升为候选规则。相同提取器、源字段绑定、目标作用域和输出关系可以参数化复用；实际对象编码保留为行字段，不硬编码成示例中的 M17。

需要 LLM 的部分只限于从多个证据包提出可复用的选择条件或映射语义。生成后做类型检查、反例检查、与原始样本结果比对及留出规则族测试。不存在足够留出资料时标 `generalization: unvalidated`，仅回放已覆盖快照，不宣称适用于任意新表。

对有明确来源规范的映射，规则可在其声明范围内执行；对样本归纳规则，越出验证范围的记录转为未决或重新发现，不直接扩大 selector。测试集用于评价，不回流改变规则后再用同一测试集报分。

### 3.2 批量执行

按表扫描 → 计算 selector 三值结果 → 提取身份与引用 → 目标索引/解析器 → 检查范围、条件和证据 → 生成断言。多个规则重叠时不采用“第一条命中就结束”；合并相容结果，互斥或冲突结果留待决策。

字面值规则产生 `has` 或其派生关系；目标是对象时必须使用对象关系。`false` 记不适用；`unknown` 记未决。缺失必需输入字段记规则执行错误，不能删除该条件后继续。

输出按稳定来源顺序分片，断言 ID 使用共同规范。运行到断点后可从导入分片/规则版本恢复；恢复时检查输入与规则哈希，避免新旧快照拼接。

## 4. 全局匹配与身份归一

### 4.1 候选及约束

复用路线2的精确、词法、语义候选并集，按业务域、版本、对象角色等缩小比较范围。参考已证实的邻居关系做局部一致性检查，例如指标依赖相同度量可以支持进一步比较，但不能独立证明指标同一。

候选对分四类分别处理：源记录对应某对象；某对象属于某类型；不同定义表达同一概念；不同来源记录指向同一身份。禁止以一个统一的 `same_as` 分数取代四个任务。

硬约束包括完整身份范围、已声明的互斥类型/版本条件、关系端点类型和已知口径冲突；信息缺失记 unknown。图路径长度和连通性不是事实证据；不为让图连通而补边。原型不必引入 Steiner Tree 或全局复杂优化器。

### 4.2 合并规则

只在共享已确认标识、明确跨源身份映射等证据足够时建立 canonical 映射。源对象保留，新增：

```yaml
source_object_id: source_a:metric:M17:v1
canonical_object_id: enterprise:metric:GM:v1
scope: {namespace: enterprise, version: v1}
decision: {status: accepted, method: explicit_identity_mapping}
evidence_ids: [identity_mapping_row]
```

这是一条身份映射记录，不增加一级业务关系。名称相似只保留候选。A≈B、B≈C 不自动推出 A=C；每次加入一个融合组，都检查整组已知身份、口径和条件是否相容，有冲突便不自动归并。

`Term` 与其指代的指标/维度保持两个对象，可用 `points_to` 派生关系表示指代；不因名称相同把术语对象吞并到指标。维度成员的身份含维度体系和层级，不把不同地区体系的“华东”强行统一。

### 4.3 断言融合

先按 canonical 映射转换视图中的端点，原断言保持不变。只对相同主体、关系、客体/字面值、作用域和规范化条件的断言合并证据集合。

同来源的重复摘要、转述、模型复述只算同一证据来源；存在 `derived_from` 链时不可当独立多数票。两条边若条件不同则并存；能否合并条件须有受限逻辑证明，首版直接保留两条以免错误简化。

字段单位、公式、期间或范围相矛盾时输出 conflict，附双方来源。一般性文档不自动覆盖具体 API 配置；反过来配置也不用于否定其范围之外的文档。冲突按声明 scope 划分，无法划分则不接受。

## 5. 增量失效

依赖索引记录 `source_ref -> extraction/knowledge claim -> mapping rule -> object/assertion`，另包含 ontology/policy/model/prompt 版本。采用本地表即可。

| 变化 | 最小处理 |
|---|---|
| 源新增记录 | 对适用且范围已验证的规则执行，未覆盖部分转路线2候选发现 |
| 公式或编码改变 | 失效相关绑定、关系和下游融合；重算受影响对象 |
| 来源删除 | 移除该来源的支持；断言仍有其他有效证据时重新校验，否则撤回/未决 |
| 文档版本改变 | 重检引用该文档的 claims 和关系；缓存键不能只用文档标题 |
| 映射规则改变 | 重算规则所覆盖的分区，不重用旧版本断言 |
| 本体类型/关系改变 | 当前冻结运行不变；下一版本重验相关规则和输出 |

没有稳定主键时，跨快照对应能力受限。对于只含文件哈希+行号的身份，首版重算整个受影响文件分区，不声称能准确识别任意行的更新和删除。

增量结果必须与同快照完整重算结果做等价比较，包括撤回和未决项；只比较新增边不足以证明正确。

## 6. SAND 可选实验

具体源码与接口依据见[共同来源说明](../shared/sources.md)。接入步骤：

1. 独立环境固定所核提交，确认 `IAssistant.predict`/`predict_entities` 的实际输入输出和依赖。
2. 只将有限的内部类型、对象关系和代表记录转换为 SemanticModel 所需形式，保留内部 ID 与临时 URI 的双向表。
3. 明确接入的是哪一个可运行算法。若仅编写一个包装自有算法的插件，评测结论只能是“适配可用”，不能声称获得新算法增益。
4. 条件、n 元关联、字面值限定等无法原生表达时保留 sidecar；往返检查必须还原原语义。无法安全表示的工作项不交插件处理，标 unsupported。
5. 插件只返回候选，经过同一身份、条件和证据校验；不能直接写最终本体。

SAND 依赖复杂、需要 Web 交互才能完成或所选算法未实现时，实验状态标 unavailable，继续默认本地流水线。用户不需要为自动抽取进入其人工标注界面。

## 7. 评价与完成条件

主要比较 E3 与固定 E2F：映射在留出记录上的关系准确率/召回、错误传播率、身份误合并率、条件保留率、增量与全量等价性、LLM 总成本。新类型发现能力不属于冻结映射阶段的优势指标。

具体使用 C08、C09、C12—C16。SAND 额外报告导入/导出损失、可覆盖任务比例、插件依赖和耗时，不只报告候选评分。所有未决和未执行分区进入总表。
