# 路线 2：本体与元数据图浏览

`build` 结束时自动生成 `viewer.html`；已有运行可执行：

```bash
cd route2
uv run ontology-r2 visualize --run runs/<run-id>
```

页面只保留“本体结构”和“元数据图”两个入口，不显示运行指标看板。左侧搜索节点，中央显示所选节点的局部结构，右侧显示完整的直接属性和连接，证据放在详情底部。图中数据属性最多展开 5 个、对象关系最多展开 3 个，物理表的列最多展开 6 个；这是绘图上限，右侧仍列出当前对象在本体文件中的全部直接属性。源记录类型与业务类型分组；物理表记录的结构映射不等于从业务记录归纳出的指标、度量或维度。

本体结构读取 `ontology.yaml`。对象节点详情列出上位/下位类型、`has` 数据属性、定义域或值域覆盖此对象的关系类型，以及已载入的实例预览。若业务类型没有数据属性绑定，页面明确显示“尚未构建”；若保存了 `source_properties`，另列定义来源字段。数据属性详情列出类型、所属对象、源字段绑定和证据；`mapping_status: definition_record_only` 表示属性只在定义记录上得到支持，不能推断每条事实实例都有该属性值；`observed_fact_value` 才是通过来源行回查的实际数值映射。关系节点详情列出上位关系、定义域、值域、端点依据及证据适用范围。已绑定的业务事实实例可查看观测值、坐标、字段绑定引文和来源行；坐标当前以原值保存，不自动声称已链接到维度成员对象。

业务类型若有完整核验的等价组，右侧另列规范类型、已验证等价的来源类型、逐对判定说明和两端定义/公式引文；原始来源类型仍可逐个点开。该展示读取 `ontology.yaml` 的 `canonical_type_id`、`equivalent_type_ids`、`type_equivalences`，具体模型决策、预算和未决项见同次运行的 `type_equivalence_steps.yaml`、`type_equivalence_assertions.yaml`、`type_equivalence_coverage.yaml`。同名但未核验或被判不等价的节点仍分立显示；界面上的归并标记只表示该输入快照的有据判定，不是跨运行身份确认或独立业务语义验收。

元数据图读取 `meta_graph.yaml`、`association_rules.yaml` 和 `field_candidates.yaml`。选中表后只展开该表的列、声明约束、来源文件、源记录类型映射及少量相邻表，避免全图交叉线。技术连接分为声明外键、已核验技术匹配、部分命中和待核验候选；这些状态都不自动证明业务关系。表节点显示 DataHub URN（若运行产物提供），也可跳到对应源记录类型。这里是**本地 DataHub 兼容元数据图**：DataHub 适配器可离线导出表/列元数据，但页面没有连接 DataHub 服务端，也不宣称具备其血缘或图查询能力。

页面把源文本以文本节点写入，不执行其 HTML；SQLite 中对象、实例和证据只做有界预览。图里没有出现的节点或实例不能解释为数据库中不存在，完整产物应查看运行目录。浏览器验收使用 `fact-config-group-20260925` 的 6 行受控运行：利润业务类型显示 4 个定义记录属性及 1 个对象关系；公式属性详情可读到源字段绑定和原文证据；元数据页可查看 DataHub URN、主键、表到源记录类型映射。两种图谱切换及节点点击未出现 JavaScript 错误。该实验只验证界面与产物契约，不证明真实业务本体质量。
