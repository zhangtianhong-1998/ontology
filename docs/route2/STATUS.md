# 路线2当前实现状态

以下状态对应仓库 `route2/` 的代码和合成数据测试。用户提供过数据机运行统计，但仓库没有真实业务数据，本文未独立复现该结果；Windows 真机运行也尚未验证。`complete` 只表示本次配置下执行与结构校验完成，不表示隐含业务关系已全部发现。

| 部分 | 当前状态 | 证据与边界 |
|---|---|---|
| YAML/CSV 导入、元数据图、记录身份 | 已实现 | `storage.py`、`pipeline.py`；声明外键保留原貌，未推断的关系不写成外键 |
| P01 字段统计口径 | 已实现首版 | `profiling.py` 按不超过 32 列分组聚合；区分 CSV 空字段、带引号空字符串、空白和可用值，近似基数明确标注。CSV 无法还原原库 NULL 语义 |
| P02 频次与分层取样 | 未实现 | 目前只保留前 2048 行的有限取值样本；没有精确频次、高频/稀有/反例配额 |
| P03 字段候选召回 | 已实现基础通道 | `discovery.py` 用声明外键、字段名、有限原值倒排提出候选；候选召回排除本次输入中确认全空、审计时间/元信息及常见敏感字段，保留声明外键。未做结构化 JSON 引用、文本/FTS 候选并集，预算外字段与候选列在 `discovery_coverage.yaml` |
| P04 候选精确验证 | 已实现单列首版 | 对获选字段对全输入核验匹配、重复、缺目标及条件内外计数；支持显式 selector/作用域参数，但尚未自动提出这些条件或复合键 |
| 列角色与联合行例 | 已实现有界首版 | `column_roles.py` 将本次输入中确定全空、明确审计时间/元信息、技术主键及常见敏感字段的值移出语义提示词；`Dataset.context()` 还会隐藏常见凭据/个人信息列的行样本和 `distinct_sample`。物理列与直接映射仍保留。`row_bundles.py` 从已核验的原值相等候选中选取目标唯一的匹配记录，最多 2 对和 1 条反例，默认每候选取 1 对，不推断关系 |
| 定义记录与别名召回 | 已实现有界候选 | `concept_candidates.py` 输出定义记录候选及证据，少量候选进入增量提示词；`value_aliases.py` 输出原值/规范化/别名样本候选及碰撞、反例，但只作为独立诊断，不参与关系计划。均有覆盖范围，未做业务同一性确认 |
| 关联规则与发现 Agent | 新增可选原型 | `association_rules.py` 把已发现字段对固化为快照内规则，重新统计目标唯一、缺失、多义与反例；可选 AgentScope ReAct 只经有界只读工具提出受限规则。当前仅编译单列恒等变换，`checked_technical` 不是已确认的业务关系；真实数据上的发现率未测 |
| 语义卡与实例检索 | 新增可选原型 | `semantic_cards.py` 扫描全部 CSV 行，按表配额写入磁盘 SQLite 卡片和中文 2/3 字 n-gram FTS5；规则/配置/锚点/日志表的记录只作引用或上下文卡，不作为概念定义种子。`instance_bundles.py` 以词法候选及可选本地向量按 RRF 排序，并在种子/关系包名额内分散表和根类型、后置纯数字碰撞。入卡、种子、向量卡数量均受限并报告遗漏；尚无高频/稀有/反例的正式分层选样及 Gold Recall@K |
| 跨表组包与组级增量 | 新增可选原型 | 已核验技术规则生成关系证据包，定义卡生成概念候选包；同根定义表或锚点/定义表共享定义键时，先作为概念对齐线索，不强行变成对象关系。`group_incremental.py` 分别输出关系计划或业务概念及 `record→concept` 对齐，检查引用、范围与规则，再可选 Judge。关系须引述同一核验正例双方**非关联键、未截断记录值**；编码相等或字段注释本身不够。新概念至少有一条完整的 `exact` 定义来源，成员/字段记录不能作为父概念的 `exact` 来源。只运行一次有界组调度，不保证百万条不同定义都进入模型 |
| P05 语义与计划 | 部分实现 | 少量已核验候选摘要和联合行例进入逐表 LLM 上下文；关系计划仍由模型提出并由现有校验器检查，没有“语义支持→转换复验→自动编译”的完整状态机 |
| P06 对照评估 | 未实现 | A0/A1/A2/A3 候选召回、关系质量与成本对照尚未运行 |
| RIGOR 式增量、本体 YAML、记录关系执行 | 已实现原型 | `incremental.py`、`relations.py`；超时会停止该表相同请求的语义修复，保留直接映射。真实数据语义质量和百万行全量完成率尚未验证 |
| 运行进度 | 已实现 | `progress.py` 按阶段向 stderr 报告进度；可用配置或 `--no-progress` 关闭，不改变 CLI 的 JSON stdout |
| 企业检索与外部模型 | 已实现原型 | AgentScope ReAct/stdio MCP、RDF/CDM 导入；关闭 MCP 时生成提示词改用数据库证据。空白及 `None`/`null` 等占位正文会被拒收并记录原因。真实企业 MCP 契约与正文获取方式未验证 |
| 可选本地 embedding | 已实现原型 | `embedding.py` 本地加载 Qwen3；外部本体、已有 core 与 MCP 命中仍按原路径使用。新实例组包可对**上限内的去重定义卡**编码并与词法候选融合，超限或缺模型会报告向量通道未运行；不编码全部 CSV 行，也不扩大 MCP 服务端未知的文档召回。真实业务检索质量未验证 |
| LLM 双接口、思考开关、本地可视化 | 已实现 | `transport.py`、`visualization.py`；页面增加业务概念、记录对齐和语义组增量视图，显示 ID、定义、源记录与原文证据的有界预览。合成数据已用配置的火山引擎端点做有界调用，真实业务语义质量仍需验证 |
| 实例物化成本与运行状态 | 已实现开关和限额 | 真实数据示例默认关闭全量实例物化，按每表前 3 条记录做页面预览，关系计划命中时仍物化端点。打开全量模式后，每条记录的每个非空映射列各写一条 `has` 断言；`manifest.partial_reasons` 说明部分完成的原因。尚无按表列出的未物化区间 |
| DataHub 离线互操作 | 已实现可选适配器 | `export-datahub` 输出表/列的 metadata-file；合成样本经 DataHub CLI 校验并写入/读回 Lite。Lite 不提供图遍历/血缘；路线2仍使用本地图 |

程序候选发现不会把值重叠直接解释为业务关系。真实数据示例原先最多索引 64 个字段、精确核验 12 对；应以实际运行配置为准。预算外候选写入 `discovery_coverage.yaml`，新语义卡、规则和组包阶段各有覆盖报告。正常完成输出时从 `manifest.partial_reasons` 区分未核验候选、知识失败、未接受的表/组增量与记录上限；提前异常中止时查看 `manifest.error`。LLM 调用次数受表和组预算约束，不随记录数逐行调用。

仍未实现标准名到别名、编码变换和复合键的完整规则验证；列角色只是保守过滤。组级概念对象独立于“每表一个基本对象类型”的旧计划，尚未实现同表多类型分派、跨快照稳定身份、异常值分层选样或对概念质量的 Gold 评测。单个组包有字节上限，完整请求还有 LLM 层的 `max_input_bytes` 准入；两者不保证组包覆盖率。早期完整 CLI 合成试验曾把“同一指标的多表属性描述”接受成对象关系；新增防护在重放中移除了该边，但尚未把这类记录正确地对齐为同一概念。用户数据机的“0 个关系类型”问题须在同一输入与配置上重跑；合成测试不能代替真实关系质量评估。合成实验与未测项目见[水果经营实验记录](EXPERIMENT_FRUIT.md)。
