# 路线2当前实现状态

以下状态对应仓库 `route2/` 的代码和合成数据测试。用户提供过数据机运行统计，但仓库没有真实业务数据，本文未独立复现该结果；Windows 真机运行也尚未验证。`complete` 只表示本次配置下执行与结构校验完成，不表示隐含业务关系已全部发现。

| 部分 | 当前状态 | 证据与边界 |
|---|---|---|
| YAML/CSV 导入、元数据图、记录身份 | 已实现 | `storage.py`、`pipeline.py`；声明外键保留原貌，未推断的关系不写成外键 |
| P01 字段统计口径 | 已实现首版 | `profiling.py` 按不超过 32 列分组聚合；区分 CSV 空字段、带引号空字符串、空白和可用值，近似基数明确标注。CSV 无法还原原库 NULL 语义 |
| P02 频次与分层取样 | 未实现 | 目前只保留前 2048 行的有限取值样本；没有精确频次、高频/稀有/反例配额 |
| P03 字段候选召回 | 已实现基础通道 | `discovery.py` 用声明外键、字段名、有限原值倒排提出候选；未做结构化 JSON 引用、文本/FTS 候选并集，预算外字段与候选列在 `discovery_coverage.yaml` |
| P04 候选精确验证 | 已实现单列首版 | 对获选字段对全输入核验匹配、重复、缺目标及条件内外计数；支持显式 selector/作用域参数，但尚未自动提出这些条件或复合键 |
| 列角色与联合行例 | 已实现有界首版 | `column_roles.py` 将本次输入中确定为空、明确审计时间及技术主键列移出语义提示词；全字段直接映射仍保留。`row_bundles.py` 从已核验的原值相等候选中选取目标唯一的匹配记录，最多 2 对和 1 条反例，默认每候选取 1 对，不推断关系 |
| 定义记录与别名召回 | 已实现有界候选 | `concept_candidates.py` 输出定义记录候选及证据，少量候选进入增量提示词；`value_aliases.py` 输出原值/规范化/别名样本候选及碰撞、反例，但只作为独立诊断，不参与关系计划。均有覆盖范围，未做业务同一性确认 |
| P05 语义与计划 | 部分实现 | 少量已核验候选摘要和联合行例进入逐表 LLM 上下文；关系计划仍由模型提出并由现有校验器检查，没有“语义支持→转换复验→自动编译”的完整状态机 |
| P06 对照评估 | 未实现 | A0/A1/A2/A3 候选召回、关系质量与成本对照尚未运行 |
| RIGOR 式增量、本体 YAML、记录关系执行 | 已实现原型 | `incremental.py`、`relations.py`；超时会停止该表相同请求的语义修复，保留直接映射。真实数据语义质量和百万行全量完成率尚未验证 |
| 运行进度 | 已实现 | `progress.py` 按阶段向 stderr 报告进度；可用配置或 `--no-progress` 关闭，不改变 CLI 的 JSON stdout |
| 企业检索与外部模型 | 已实现原型 | AgentScope ReAct/stdio MCP、RDF/CDM 导入；关闭 MCP 时生成提示词改用数据库证据。空白及 `None`/`null` 等占位正文会被拒收并记录原因。真实企业 MCP 契约与正文获取方式未验证 |
| 可选本地 embedding | 已实现原型 | `embedding.py` 本地加载 Qwen3；`external.py` 对外部本体卡用 FTS5 + 精确余弦并集及 RRF 排序；`incremental.py` 只召回已接受表作上下文；`knowledge.py` 只重排 MCP 已返回的标题/片段。不会扩大未知 MCP 服务端的文档召回，也不编码全部 CSV 记录。真实业务检索质量未验证 |
| LLM 双接口、思考开关、本地可视化 | 已实现 | `transport.py`、`visualization.py`；页面显示类型 ID/定义及每条预览记录的有限属性，实际模型服务仍需用户配置 |
| 实例物化成本与运行状态 | 已实现开关和限额 | 真实数据示例默认关闭全量实例物化，按每表前 3 条记录做页面预览，关系计划命中时仍物化端点。打开全量模式后，每条记录的每个非空映射列各写一条 `has` 断言；`manifest.partial_reasons` 说明部分完成的原因。尚无按表列出的未物化区间 |
| DataHub 离线互操作 | 已实现可选适配器 | `export-datahub` 输出表/列的 metadata-file；合成样本经 DataHub CLI 校验并写入/读回 Lite。Lite 不提供图遍历/血缘；路线2仍使用本地图 |

程序候选发现不会把值重叠直接解释为业务关系。真实数据示例默认最多索引 64 个字段、精确核验 12 对；超过预算或样本截断会在 `discovery_coverage.yaml` 中标明，并使执行状态成为 `partial`。正常完成输出时可从 `manifest.partial_reasons` 区分候选未核验、知识失败、表增量未接受和记录上限；提前异常中止时查看 `manifest.error`。LLM 调用次数仍按表/候选问题受预算控制，不随记录数逐行调用。

仍未实现标准名到别名、编码变换等跨表规则的全输入验证和自动编译；列角色只是保守过滤，联合行例只覆盖预算内、精确核验的原值相等候选。当前每表仍只指定一个基本对象类型，虽然定义记录候选已进入提示词，尚未从大量实例名称稳定归纳“收入”等共享度量概念，也未实现同表多类型分派。用户数据机的“0 个关系类型”问题须用新代码在同一数据与配置上重跑，合成测试不能代替真实关系质量评估。

安装与离线边界见 [Windows 离线运行说明](DATAHUB_OFFLINE.md)，下一步任务及验收条件见 [implementation.md](implementation.md)。
