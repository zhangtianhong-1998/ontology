# V14：先验证语义正确性与事实复用

日期：2026-10-07。分支：`codex/ontology-correctness-v14`，基线：V13 `1be2ff59`。

本轮采用用户提供的审查意见作为待验证问题，不把报告中的推测直接当成数据事实。先复现错误接受，再补正确接受和覆盖反例。本轮没有修改 V13 产物、清空旧实验或调用外部 LLM；也没有扩大预算或启动新的全量抽取。

## 1. 需求与验收

| 编号 | 用户故事 | 本轮验收边界 |
|---|---|---|
| V14-01 | 同名概念可以复用，但经营范围、单位和计算口径不能被合并掉 | 截断定义、小数口径、错误固定目标必须拒绝；完整来源及真实别名仍可通过 |
| V14-02 | 关系来自正确的引用与声明，不能依赖偶然重合 | JSON 无关分支不能消歧；否定/条件句不能成为肯定成员关系；数字风险未知不得视为安全 |
| V14-03 | 旧本体应减少重复抽取，不能阻止新概念 | 加入词面相近的无关类型后，原来可归纳的事实列仍能处理；已知同身份缺范围则保持未决 |
| V14-04 | 有限关联预算优先调查有价值的缺口 | 范围歧义、部分匹配、声明冲突和未核验分队列；保存游标，未检查不等于无关系 |
| V14-05 | 类型能绑定业务记录，形成可追溯的事实 | 从来源配置编译类型/关系，再产生含对象、地区、期间、单位和值的事实；不是只统计定义实例 |
| V14-06 | 新数据优先执行既有映射 | 独立复用入口重验来源与字段合同；新增同结构记录不调用模型，失效来源/未知字段进入待处理 |
| V14-07 | 运行成本和完成状态可信 | 内部重试/格式修复占用阶段请求额度；运行参数变化不作废相同生成缓存；截断范围必须传递 |

这些案例证明指定合同下的程序行为，不证明未知企业数据的抽取准确率。代码保持普通函数、小数据模型和独立编译入口；不引入通用多 Agent 调度框架。

## 2. 正确性修复

### 完整定义与目标身份

新增公共 `semantic_validation.py`。单项定义、组合定义及模板成分共用完整性检查：不能只引用“客户是购买产品的主体”，却丢掉“仅限直营渠道”。未进入类定义的限制必须完整保存在定义参数或适用范围中，单独留在证据或匹配条件里不够。

来源明确写成“类定义。实例：{坐标}”时，允许实例部分通过显式槽位保留；要求两条变化见证、真实实例列，并保存可重放合同。“仅限{坐标}”不能被当成实例段。当前采用保守规则，不声称程序可以理解任意自然语言的省略含义。

固定与变量度量槽位都核对来源完整名称或已验证别名；引文存在、目标属于 Measure 不能证明目标正确。缺少目标证明的旧模板拒绝重放。

类型等价的规范化只处理明确的呈现空白，保留小数点、比例、日期、区间和运算符。`1.0%` 与 `10%`、`1 0` 与 `10` 不再变成同一文本。

### 关系证据

- JSON 保存完整路径；范围字段只能来自引用所在的同一 JSON 对象。其他分支的值不能用于消歧。发现和重放共用这一边界。
- 确定性成员通道要求完整肯定声明。关键词仅用于召回；否定、条件、假设及合同外文本进入未决。
- `numeric_overlap_only` 使用 `true/false/null`。精确核验根据实际匹配值重新计算，即使这些值曾被高频过滤。没有匹配值时为未知；别名变换、规则编译、逐表提示词和页面均保留这一状态。
- 稀疏关系文本采用非空 distinct、内容哈希和有界分层样本；记录未检查的 distinct 值与超长文本。前 16 行为空、第 17 行有声明的场景不再因前缀读取消失。有限样本仍可能漏召回，因此不会把未命中声明为不存在关系。

## 3. 复用和关联调度

事实处理顺序改为“召回 → 用最终绑定校验确认可复用 → 绑定或继续归纳”。词面相近的耗电量不能阻止设备发电量归纳。若确实召回同一身份、但无法证明范围或单位，则返回未决，不能另造一个无范围的新类型绕过限制。

关联 Agent 按缺失证据分队列，并在每类内部保持来源字段和连接族的轮转。V13 的 6,030 个候选只读回放中，12 个名额分到 6 个范围歧义、6 个部分匹配；没有向模型提交，也没有因此接受新关系。此结果只说明调查对象发生了变化。

继续游标位于 `association.agent.scheduling.next_cursor`，可作为 `association_rules.agent_candidate_cursor` 传入。候选和检查内容变化时，旧游标重置。本轮没有增加自动无限循环。

## 4. 两种增量入口

**同一次实验恢复**继续要求输入快照、模型、提示词、排除策略及语义代码一致。`semantic_code_hash` 排除展示 HTML、可视化和进度代码；完整 `implementation_code_hash` 仍写入 manifest。改页面不会作废语义检查点，改编译器仍会。

**新快照事实复用**使用 `ontology_reuse_bundle.yaml` 和 `reuse-facts`。包保存类型、已接受字段映射、完整来源证据、重放键及语义契约。新快照重新定位来源、验证完整定义、字段声明、范围和单位，重建当前快照证据和事实 ID。内部 YAML 本体契约也保存指纹；自定义契约通过 `reuse-facts --profile /path/to/internal_model.yaml` 指定，契约不同会拒绝重放。代码契约、来源或字段失效时要求重新验证，不放宽原有恢复检查。

```bash
# 在 route2 目录运行；输出目录必须不存在。
uv run ontology-r2 reuse-facts \
  --dataset /path/to/new-data \
  --bundle runs/previous/ontology_reuse_bundle.yaml \
  --output runs/reuse-new
```

当前只执行可重验的事实字段映射及其来源类型。关系模式保留供检查，但跨快照关系需要独立编译器重放；来源片段不能完整定位、等价融合、任意跨表计算 JOIN 和稳定实体身份均不能据此认定完成。命令输出 `reuse_pending.yaml`、`reuse_coverage.yaml` 和业务事实文件，未决项及候选/物化上限均使覆盖状态保持部分完成。新快照仍需重新导入和验证，零模型调用不等于零数据访问；聚合得到的单位/身份见证、等价迁移等尚不能作为可直接重放的字面来源。

## 5. 小规模验证

可复现脚本：[`verify_correctness_v14.py`](../../route2/scripts/verify_correctness_v14.py)。语义提案为明确标记的本地固定决策，来源 CSV/YAML、类型编译、关系编译、事实绑定和重放使用生产实现，没有预先把最终本体写入结果。

```bash
uv run python scripts/verify_correctness_v14.py --output runs/correctness-v14-check
```

输入是独立的设备发电场景，而非水果表：定义表、关系配置表、业务事实表。验证得到 4 个类型、2 条配置关系、2 个事实；增加一条同结构事实后复用得到 3 个事实，外部 LLM 调用为 0。事实保存设备、地区、期间、单位、值和来源定位。更改租户或定义限制时不能继续绑定，生成 0 个事实并保留原因。

空本体与加入“耗电量”的本体各生成 2 个发电量事实，说明相似候选不再阻断归纳。追加快照仍有 2 条关系模式等待重放，表用途报告也保留未决，因此不能称为完整关系复用。事实数值取自来源记录，本次没有执行数值公式求值，也没有建立跨快照稳定设备实体身份。

结果见本机 `route2/runs/correctness-v14-controlled-20261007/report.json`；[小报告与调度回放证据](../../experiments/correctness-v14-20261007/README.md)已归档。最终全套回归 **1,385 项通过，0 失败**；该结果包含错误接受、正确接受、预算、恢复、CLI 及页面脚本用例，不是业务质量分数。

## 6. 缓存、预算和界面

生成缓存只取请求内容、模型、服务地址及影响生成的参数。预算、间隔、超时和 JSON/SSE 传输选项变化不使同一语义请求失效；提示词、证据或模型变化仍产生新键。新命名空间不会误读旧格式缓存。

`StructuredLLM.call_budget()` 在实际请求准入层执行限制。事实模式归纳、事实字段绑定和关联 Agent 的内部修复/重试均计数；阶段决策数与实际请求数分开。上限 1 的本地 HTTP 失败场景只发送 1 次，不会通过自动重试突破限制。

页面对未知数字风险显示独立提示，默认收起未核验或纯数字重合技术边；声明外键仍展示。已做页面 JavaScript 和布局几何回归，本轮没有完成浏览器交互验收。这里没有声称初始适配、缩放拖动、节点详情和不同规模图均已由浏览器验证。

DataHub 继续提供标准标识和离线交换格式；元数据图由本地 schema、来源结构和已核验技术规则构建，不由 DataHub 服务推断业务关系。技术边保留条件、来源和风险，不能直接冒充业务本体关系。

## 7. 下一轮验收与待办

1. **跨快照关系重放**：逐条重验关系的定义、两个端点、范围及引用路径，再生成新快照关系实例；目前只完成事实字段复用。
2. **多层本体结构**：尤其 Measure，先明确来源父类声明、单位、算式、计算参数和过滤范围合同，再支持逐层插入；不通过删除业务限定词生成父类。
3. **独立数据泛化对照**：删注释、改列名、调整表拆分、打乱行序、同码异域和标准名/别名分列。已有局部反例不替代这一完整矩阵。
4. **语义质量与覆盖**：分别报告类型/关系正确率、定义绑定覆盖、事实实例化率、未处理范围及新增语义请求成本。孤立节点不能靠强行加边消除。
5. **代码职责整理**：公共验证已开始集中；主流程和组级构建的大函数、剩余私有跨模块调用以及统一阶段结果接口仍待逐步拆分。
6. **环境和界面**：独立浏览器交互、Windows 无 Docker 离线依赖及 embedding 实机验收仍待完成。

通过小闭环不代表上述待办已完成。独立数据和界面验收后再决定是否开展新全量实验；本轮不靠扩大调用预算评估算法是否改善。
