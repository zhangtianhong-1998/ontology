# 关联搜索与本体增量重构

本轮分支：`codex/ontology-association-rebuild`，起点 `3d994045`。目标是修复候选漏召回、错误合并、重复请求和元数据展示问题，再在本机完整合成数据上验证。数据机真实数据不在本机，不能据此确认真实数据效果。

## 已确认的问题与处理

| 问题 | 实现调整 | 验收依据 |
| --- | --- | --- |
| DataHub 只在导出时出现，建图结果没有参与抽取 | `metadata_graph.py` 统一建图与查询；表和字段带 DataHub URN，核验后的技术关联带条件、转换与证据；组包查询图中的相关字段 | 声明 FK 与技术关联分开；无服务环境可建图并导出；关联进入组包上下文 |
| 关联发现依赖列名或编码形状，别名结果仅供查看 | 全量 distinct 倒排、元数据候选并集；加入数值异名候选风险标记、任意低基数条件分支；别名转换使用受限 DSL，全输入重新核验 | 异名数字编码、中文或数字判别值、标准名对别名匹配；重复别名和多目标保持歧义 |
| 列角色推断排在关联发现之后，并按整表跳过 | 调整到发现之前；逐列补缺；结合字段声明、非空实际值和分布；不再因为已有一个 name 列跳过其他列 | 无注释列、已有名称但公式列匿名、时间/维度/数值角色；引用不存在的样本值应拒绝 |
| GROUP BY 被当作业务概念证据 | distinct 只用于建立倒排和取实际元组；语义按定义模式调度，事实按字段模板绑定 | 不枚举各字段值的笛卡尔积；同坐标不同数值报告歧义；高频重复不能挤占 distinct 样本 |
| 同名、同描述但公式不同的对象会被合并 | 类型和概念身份包含完整源公式；全量定义原文作为已接受定义，模型改写单独保存 | 同名冲突公式拒绝 exact 合并；不同范围允许保持不同度量类型 |
| 配置中的否定、条件和过期内容可能变成肯定关系 | 先检查完整源字段、语义极性与条件，再裁决关系；关系谓词限定根关系及登记的派生关系 | 否定/条件/过期配置不能变成无条件边；端点及关系方向需要证据 |
| 页间增量没有复用已接受结果 | 保存 `semantic_state.json`；`--resume-from` 读取同快照、同模型与提示词契约的状态；已接受包跳过，未决包保留 | 恢复结果保留原本体与关系；过期输入、契约变化拒绝复用 |
| 元数据与本体在界面混淆 | 保留本体/元数据两视图；元数据默认表级，可展开字段；圆形节点、缩放平移、关系标签；右侧显示继承属性及证据 | 页面只把已接受本体关系画为业务边；技术候选不伪装为血缘 |

## 处理顺序

1. 导入 YAML/CSV，保存快照与源记录身份；全输入字段统计保留 NULL、空字符串、空白的区别。
2. 规则先排除空列、审计列与敏感列。无法判定的语义列交给有界字段角色判定，返回的每个样本引用必须与源记录一致。角色只决定候选入口，不直接决定本体类型。
3. 对候选字段建立 distinct 值倒排，召回异名列。对值重复较多的引用检查同表低基数判别列，生成条件分支，避免先枚举所有字段组合。
4. 标准名、别名、大小写和全半角转换必须经过完整输入验证。输出范围、覆盖率、歧义和缺目标记录。没有匹配结果不表示没有关联。
5. 将已核验技术关联写入元数据图。按关联反向定位实际记录，组包仅包含需要的定义、名称、公式、单位、范围与证据；ID 和时间字段保留映射，避免把大量取值送入模型。
6. 对完整语义字段相同的定义按模式调度；模型提出类型、关系，程序编译校验并复核。批量调用中的每个包仍有独立 ID、证据范围和裁决，不能相互借用记录。
7. 类型模板只复用到符合完整字段契约的记录。记录 ID 不合并，引用差异单独保留。业务事实按字段模板绑定，数值变化不重新生成本体。
8. 对已接受的度量和指标解析源公式，构建表达式树、操作数绑定和 `calculation_dependency`。自然语言公式、未知符号、同名歧义与循环保留未决；不猜计算依赖。
9. 输出 YAML 本体、映射、实例、计算契约、覆盖报告和 HTML。完整输入扫描、本体候选处理、实例物化分别计数。

## 可复用契约

技术规则包含 `source`、`target`、`selector`、`scope_bindings`、`transform` 和全输入核验结果。转换仅支持 `identity`、`nfkc_whitespace_casefold`、`source_alias_items`、`target_alias_items`、`both_alias_items`。禁止执行模型生成的 SQL 或 Python。

`semantic_state.json` 用于同快照续建。它包含已接受本体、概念包状态、列角色、证据和待定关系。恢复还必须匹配 `implementation_code_hash`，该值与 manifest 共用整份生产代码的哈希；代码改变或旧检查点缺少该字段时，在恢复证据之前明确拒绝。此哈希也包含浏览页面，因此页面改动同样会使旧状态失效；这是保守的版本边界。原始模型响应缓存仍可经过新编译器重新校验，不能等同于沿用旧接受结论。输入变化后，旧记录证据不能直接沿用；字段模板须检查声明与适用条件，重新绑定当前数据。

`calculation_contracts.yaml` 保存完整原式、表达式树、操作数角色、类型绑定和未决原因。`depends_on` 是一级关系，`calculation_dependency` 是派生关系；分子、分母、被减数、减数等是关系参数，模型不能自行造谓词名。

DataHub 在此版本负责元数据格式互通。元数据图由本地程序从导入内容构建与查询；没有运行 DataHub 服务，也不声称 DataHub 自动发现了隐式关联。`datahub-metadata.json` 是本地文件，不会上传到网站。

当前 DataHub 导出范围为表属性、列定义和声明主键，仅包含 `datasetProperties`、`schemaMetadata` 两类 aspect。技术关联、外键及其他约束保留在本地 `meta_graph.yaml`，尚未导出为 DataHub 关联或血缘。组包读取本地图时保留 `declared`、`checked_technical`、`observed_subset` 原始状态及数字值重合风险；这些技术证据不能直接作为业务关系。

## 实验与验收

- 先跑无模型预处理，确认完整输入行数、候选/核验数、定义模式数和遗漏范围。
- 完整合成实验使用 23 张表、约 110 万行；公开配置不包含密钥。模型读取本机环境变量，关闭企业知识召回，关闭思考模式。
- 共享模型预算仍为 800 次。批量概念请求降低重复指令开销，修复、复核、角色、关联 Agent 等均计入预算；到上限必须明确报告未处理候选。
- 记录实际调用、缓存、失败、token、耗时与每阶段覆盖。扫描所有行不等于每行都有已接受的业务语义。
- 测试覆盖工程约束和已知反例；不能用测试通过、本体节点增多或图连通来代替业务正确率。

代码要求：原型模块保持简洁；公共契约、调用顺序、拒绝条件写短注释；不要新增服务部署依赖，不为目前的水果表硬编码特殊表名或列名。

具体实验结果在同目录实验报告中记录。此文档只描述实现契约，不把尚未完成的实验写成已通过。


## 预处理实测后的补充修复

- 字段角色冲突优先处理：明显 ID/键不能因名称中有 rule/formula 就变成公式；原值强制保留为引用，不受普通引用预览数量限制。规则内容与 rule_type 参数分别保留。
- ReAct 工具返回可回查的摘要，标明省略字段与原产物位置；完整候选和 Agent 核验结果保存到 association_rules.yaml。默认每轮最多 4 次只读工具调用，并为最终 auto 结构化提交保留机会。
- 明确来源的“不限”范围可用 unrestricted 表达，不能把全国、年份粒度、空值或包含例外的范围转成无限制。定义中的粒度可保存为参数；地区范围包含哪些成员、参数如何约束事实坐标，仍需独立证据和实现。
- 事实单位声明支持“单位元”“单位为元”等明确写法，同时拒绝把“单位成本”当单位。不同单位不自动换算。

## 概念名称与定义参数

每个概念包提供 `canonical_name_choices`，仅列出可作 exact 对齐的来源记录中完整的 name/alias。模型应使用其中的原名。同名的“苹果经营利润”可以分别代表扣费前、扣费后或不同适用范围；它们靠完整定义、公式、参数、单位和 ID 区分，不靠模型加括号改名。

程序只允许一种显示名称规范化：模型名称恰好是唯一的完整来源名称加一段括号注记时，恢复来源原名，并保存 `proposed_label`、`label_normalization` 及名称见证。括号内容不作为语义证据，不改变定义、公式或范围。改写名称、来源名称缺失、只有关联上下文支持名称的情况，继续拒绝。

`scope_roles` 区分四种用途：

| 角色 | 保存方式与边界 |
| --- | --- |
| `applicability` | 适用范围保存在 `applicability_scope`，例如来源声明的“全国”；不能为了绕过校验改作参数或无限制。 |
| `parameter` | 定义中的期间粒度、计算参数等保存在 `definition_parameters`，参与类型身份。必须有 exact 记录完整原值及可核查的字段声明或已核验计算片段；“公历年”粒度不是某条事实的年份。预算标记、计算方式等不同取值不能被丢弃。 |
| `observation` | 具体观测坐标，例如 2025、2025Q1；不能作为类级身份，也不能假称计算参数。 |
| `unrestricted` | 只有完整来源明确说明不限且没有例外时使用。原文与角色保留，不编译成要求与坐标字面相等的条件。 |

`parameter` 不意味着忽略这个字段，也不证明它与事实坐标兼容。定义参数不同的类型不能 exact 合并；共同上位类型也不能通过删除参数掩盖差异。参数与适用范围的来源保留在概念证据和数据属性中。Metric 的 `aggregation_operator` 必须为 JSON `null`，完整计算仍来自自身公式；只有 Measure 才能填写有来源依据的可选运算属性。

事实字段包同时提供 `declared_unit_quote_contract`：单位若来自字段声明，模型必须复制整个声明到 `unit_quote`，不能只摘录“元”或“单位元”。单位解析成功不等于业务类型身份或适用范围已经验证。

对应回归见 `test_concept_contracts.py`、`test_unrestricted_scope.py` 和 `test_fact_schema_induction.py`。这些契约测试不代替真实模型对照；模型仍可能给出未决或被拒结果，应在实验报告中分别计数。

## 数量定义的分类证据

`business_object_quote` 为空不能证明一条定义没有经营对象。全量 v6 曾把完整定义“芒果均价，按非洲和会计期汇总。”按短名称“均价”接受为通用 Measure；来源标准名“芒果均价”也被忽略。该结果已停止使用，保留为编译回归反例。

现在，每条 exact 来源都必须单独提供通用性依据，才能归为 Measure：完整原文明示适用于不同经营对象、不绑定经营对象，或明确的经营对象范围字段声明无限制。`measure_reuse_assessment` 保存逐条来源、原文及缺证原因；`reason`、表名、短名称、运算符和空引文都不能补证。明确的业务对象范围与通用声明冲突时保持未决。范围字段仅写 `all`，却没有说明它指经营对象，也不足以证明通用性。

Metric 和 Measure 无论标为 type、instance 还是 unresolved，都必须提交匹配的分类依据和完整来源引文。改动 `ontology_level` 不能绕过分类校验。被编译器拒绝的语义增量在 `compiler_evidence_audit` 中保留逐条原因。

标准名比短名更具体时，短名不能把整条受限记录变成通用定义。可按完整来源提出业务指标候选；要抽象通用度量，则须有独立的通用定义记录作 seed，业务记录只作 related/narrower。反向同样受限：明确声明不绑定经营对象的定义不能把“预算”“排名”或“不限定”声明中的词当成经营对象，再改称 Metric。

收入、成本可以是有来源依据的通用度量。“10月年预算”“当年预算排名”中的期间、预算与排名参数也可以保留；时间参数不会自动把度量改成指标。不同参数仍参与类型身份，不能为了合并而删除。

接口查询、卡片展示的主题也不足以定义一个数量。`quantity_subject_assessment` 检查所选名称、说明的字段声明及同条记录的服务用途证据，不以表名判定。独立数量定义可以是完整的自然语言，不强制要求数学公式。服务与数量定义混在一行时，当前一条记录只能 exact 对齐一个对象；在字段定义投影尚未实现前，保留未决，不把整个服务记录等同于其中的数量。

这些检查采用有限、可核查的来源声明，无法覆盖所有自然语言写法。缺少明确通用声明的度量会少召回，陌生措辞可能留为未决；这项代价应与分类错误分别报告，不能声称已经保证业务分类正确。相关反例见 `test_measure_classification.py`、`test_definition_subject.py`。

旧的 mock 正例原先允许仅凭“可复用”或缺少分类引文接受度量/指标。相关单元测试及 `run_group_compilation_experiment.py` 的小型工程夹具现已明确通用声明，并使用完整原文作为分类引文；它们仍只验证程序契约。本次没有改写全量水果数据或语义对照数据来通过校验。

## 关系命名与部分匹配的抽取边界

登记的派生关系允许使用所属根关系的受控显示名称。例如，模型同时给出 `predicate_name: definition_reference`、`parent_relation: points_to` 和 `label: points to` 时，编译器接受这一组合，最终保存的名称仍为 `definition_reference`。`scope_constraint` 同样可使用 `related to`。自由编造的谓词、不兼容的根关系和反向端点表达继续拒绝，显示名称不会改变关系身份或方向。

`definition_reference` 还要分别核验源的引用意图与目标自身的定义归属。双方都引用第三方定义时，相同编码和两端名称不能支持彼此间的定义引用。源/目标字段及表的完整声明进入关系包；核验依据、完整原文与拒绝原因单独保存，不自动改成另一种业务关系。已接受关系的自动检查记录链接到实际来源证据，不能当作新增业务事实。

`observed_subset` 表示全输入核验中只有部分源记录能唯一匹配。此类规则可以进入有界组包，程序按原 `selector`、`scope_bindings` 和 `transform` 查询实际唯一匹配的记录对；缺目标、多义目标和缺少作用域的记录不能作为正例。完整核验计数和反例仍保留在规则产物及证据包中，`technical_coverage` 单独记录包内见证数、未展示的唯一匹配数及失败计数。

语义编译只把双方引文支持的记录对写入 `witnessed_pairs`，并绑定当前快照。即使其他记录也能唯一匹配，它们也不会自动继承这次语义判断。执行时仍检查快照、原条件、作用域、目标唯一性和见证目标；因此 **`observed_subset` 仅支持已审查的见证关系，不能扩大为全列或全表语义关系**。技术核验数、包内记录数和最终接受的业务关系数须分别报告。

对应回归见 `test_relation_contract.py`、`test_instance_bundles.py` 和 `test_association_execution.py`：覆盖受控根关系名称、错根关系与反向名称，以及原值匹配、别名转换下的缺目标、多义、条件外、缺作用域和未审查唯一记录。

## 配置引用与关联预算的修正

配置规则、参数、服务和资源记录也是可以建立关系的对象。`points_to/definition_reference` 不要求算术公式；只有 `calculation_dependency` 要求公式支持操作数。原文中的使用目的、引用声明与目标自己的定义可以共同支持一个经过核验的记录对。某条条件规则还包含其他未命中引用类型，只限制该规则的覆盖，不自动否定它已经唯一命中并有语义证据的见证；仍不能把见证推广到全部记录。

目标关键字段仅有泛泛的“对应”说明时，需继续核对其自身定义用途与完整定义正文；明确外键、指向其他表或第三方定义的声明不能用复制来的正文抵消。模型提议和复核使用同一边界，引用名称受控，不把根关系的命名要求误用于概念标签。

关系调度先覆盖不同源字段、目标字段与转换/作用域契约，再处理同一字段对的条件变体。候选分为结构引用线索、普通值匹配、数字或序号碰撞探索三层；分层只影响有限预算如何分配，不改变技术核验状态，也不证明业务关系。探索数量通过 `instance_bundles.max_exploration_rules` 配置，未进入预算的规则及各层分母必须报告。数字类型的已知引用候选不应一概被压到末尾，也不能让自增序号相同占满全部模型请求。

只有明确声明为技术资源名称的身份字段才可不参与定义调度模式。卡片的完整名称、记录 ID、原文、引用和检索文本仍保留；成员映射继续核对完整来源值，不把同一调度模式当成实体相同。一般业务名称、别名、公式、单位、期间，以及尚未核验的 JSON 引用变化继续区分。当前没有对仪表板配置的全部引用变体做语义模板复用。

元数据图默认收起仅数字重合的候选，提供按钮展开，并显示收起数量；声明外键不受此过滤影响。这只是显示选择，完整技术规则和风险仍在运行产物中，数字编码的合法引用仍可查看。
