# v11：通用关联发现与现有缺陷修复

本轮在 `codex/generalized-extraction-v11` 分支修改。企业真实数据不在本地；Claude Code 的报告作为问题线索，代码、保存的 v10 请求及产物用于核验直接原因。全量实验继续使用 v10 的 `fruit_data_v3`：23 表、1,102,238 行，不重新生成更容易通过的数据。

## 需求与实现范围

| 需求 | 本轮处理 | 验收边界 |
| --- | --- | --- |
| 不存在 API 也能运行；用户可不配关系 | 保留原值倒排、候选角色推断与联合行验证；移除维度/成员专用作用域猜测，按真实值和复合键检查候选 | 字段关联是潜在路径，业务谓词仍需来源证据；缺注释不等于可以任意补语义 |
| 抽取前发现关系，随本体构建逐步使用 | 修复引用判别字段误入描述通道；已审查记录关系可用完整模板绑定解析类型端点 | 每条关系仅覆盖核验过的实际记录，不把类型端点的所有实例相连 |
| 提示词不依赖模拟业务 | 清除生产提示词和根模型中的水果、具体企业及接口演示；保留通用身份、数量、引用与实例规则 | 测试和模拟输入仍可包含业务案例；输入本身的名称当然允许进入请求 |
| 维度和术语不因管理属性失败 | 分开 `metadata`、`provenance`、`identity`、业务范围和计算参数 | 语言与来源保留为属性；命名空间、租户、版本参与身份，不作为计算参数 |
| 修复二轮停止错误 | 单包超限使用独立状态并继续其它任务；去除重复上下文，保留付费 batch 结果；预算不足和未选任务明确报告 partial | 不可再拆的完整证据仍超限时明确未决，不静默截断，也不报告语义收敛 |
| 完整事实证据请求可执行 | 按完整定义、关联和样本单元分页；每页保留字段声明、坐标、单位，全部页面一致才编译 | 不用截断或忽略冲突来获得通过；实际数值粒度冲突仍阻止事实实例化 |
| 定义实例映射可回读 | 修复定义成员的表字段、代表记录证据与实际记录证据不一致，按完整模板回读当前记录 | 不能把代表记录证据冒充全部成员的证据 |
| 度量数值可以绑定 | 数值字段候选支持 Metric 与 Measure，继续校验单位、范围、身份及来源 | Dimension 是坐标；扩大类型候选不解决坐标下多值歧义 |

代码要求：保持原型简洁，优先修复已有接口和契约，不引入服务集群，不执行模型生成的任意代码。发现、语义判断、编译、实例化分别报告状态。

## 从真实数据报告提取的通用场景

- 无声明外键：允许从不同列名的值域、条件分支和联合行提出候选；数字自增 ID 的重合仍不证明引用。
- 同一标识在不同作用域重复：检查共同作用域字段和目标唯一性，不能因为单列重复就永久放弃，也不能全表多对多展开。
- 引用判别字段混有类别名与定义编码：保留原值及分支条件，检查目标，不预设固定前缀或固定业务类型。
- 中文描述与可解析公式混存：现有公式分类及原文保留继续生效，不把所有描述强制解释为数学表达式。
- 宽表和长上下文：报告列、样本、候选和请求预算；一个请求失败不能使其它独立任务丢失。
- 缺注释、列名不透明：模型结合多行值提出列角色候选；引用仍需程序核验。声明和统计不能唯一确定用途时保留未决。

保存的 v10 产物已有定义实例图；维度失败中可复现的问题是字段角色与编译不一致，44 条关系未提升来自已接受记录关系的端点类型限制。本轮针对这些具体原因修复。

## 关系自发现与复用的边界

程序先扫描 distinct 值、召回字段对、核验条件与目标唯一性，再用实际记录组织语义包。列名不同不排除关联。复合键候选的额外查询受 `max_conditional_pair_checks` 约束；未核验数量写入 coverage。原键已唯一时跳过额外作用域查询，目标先聚合再连接，避免多对多记录展开；候选多时仍可能产生重复扫描，耗时须由实验确认。

已有本体只作为复用目标及一致性约束。完整模板命中时直接产生实际记录绑定；未知成分、不同公式或缺失端点继续形成缺口任务。模板实例可支撑已审查记录关系的类型签名，但这不表示源记录与类相同，也不表示关系对所有实例成立。

`identity_qualifiers` 保存定义的命名空间、租户或版本。该信息进入类型身份、模板不变字段及类型等价/泛化检查；语言和维护信息仍保留原始字段与证据，不伪装成计算参数。普通记录主键不进入这类定义身份。

事实字段中的租户等身份坐标保留在观测粒度中。只有完整字段声明明确限定某个身份值，且全输入证明该坐标恒定时，才形成受限字段类型；模型漏填限定不能绕过检查。当前支持明确的身份键值声明，无法解析的限定保持未决。

## 本轮验证

新增非水果、无 API、字段改名、缺注释、复合键及数字 ID 碰撞回归；增加身份限定、模板端点、证据分页、输入超限继续队列、来源模板重放和实例边验证。mock 回归验证工程行为，不作为模型语义质量评估。

离线重建 v10 首个超限请求：旧实现精确复现 119,330 bytes；去掉重复序列化后的请求约 74,422 bytes，低于 100,000 bytes 上限，任务 ID 与四条原始记录保持一致。全量实验的 92 个输入文件均与 v10 的 SHA-256 一致。

启动前完整回归：`route2/.venv/bin/python -m pytest -q`，**1,152 项通过，75.03 秒**；`git diff --check` 通过。配置解析、模型名称、本地凭证存在性和 embedding 目录检查通过，准备阶段没有调用真实 LLM。23 项生产提示词内容检查未发现水果数据集或具体企业的硬编码示例。

实验启动记录保存实际 Git 提交。全量结束后应核对维度/术语失败原因、输入中实际对象的关系覆盖、已验证端点比例、实例映射未决项、重复调用与预算停止原因。不能用节点数量或连通率代替正确性。

## 待办

1. **静态项目知识配置**：可选的领域说明与结构化引用声明，按适用范围加入抽取和审查；空配置不增加调用。尚未新增，框架不能依赖它才能启动。
2. **周期编排 Agent**：按批次诊断缺口并调整证据包、顺序、检索与提示，不修改代码；需要受控动作、版本、成本和效果记录。当前仍是确定性的定向修复。
3. **结构化词典与 JSON 引用归纳**：将实际 JSON 路径、词条共同身份、语言及命名空间转为通用指称/成员声明；不能仅凭同值自动合并。当前字段角色修复不会自动补齐所有术语关系。
4. **未知结构的跨表配置语义**：将多跳、条件、列表及多列公式片段编译成统一可执行引用声明，逐渐减少自然语言说明不足造成的未决；本轮只修复现有标量/复合键路径和端点衔接。
5. **业务事实粒度与跨快照身份**：区分同一坐标下多条业务事件、聚合口径和重复记录；补足来源后再物化事实。当前不会删除冲突值来使实验通过。
6. **跨领域语义评测**：增加独立领域和人工标注的正确关系，做角色、关联、类型、实例分别验收。非水果工程回归不能证明任意企业数据都能自动理解。
