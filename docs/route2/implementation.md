# 路线2：实现清单与后续任务

本文中的代码、配置路径及命令均以仓库的 `route2/` 目录为基准；文档链接可直接点击。

路线2已具备独立可运行入口，不依赖路线1先完成改造。上游 RIGOR 保留原样；本轮根据源码补齐直接映射、逐表增量、core 上下文、Judge 修正和合并前校验，使用内部 YAML 契约。

## 1. 当前原型的交付范围

| 任务 | 对应 US | 当前实现 | 验证与范围 |

| T02 引用与条件 | 02、09 | `models.py`、`relations.py` | 作用域匹配、三值条件、JSON 键路径、空引用、目标歧义；不把候选回写为外键 |

## 3. 仍需实际环境验证

1. 配置真实模型后，在相同模拟输入上运行 E2L、E2O、E2K、E2F，分别观察生成方案、候选遗漏、未决和成本；模拟响应不能作为模型质量分数。
2. 获得企业 MCP 契约后，适配真实 search/fetch 参数、权限、文档定位与范围字段；当前只是本地 stdio 服务。
3. 获得真实数据后，评估表角色、跨记录关联、单位/口径冲突、根类型区分和候选召回。现有业务举例不进入真实输入假设。

以上需要尚未提供的环境或数据，代码不会用模拟结果冒充完成。

## 4. 按实验结果决定的增强项

| 项目 | 触发条件 | 首版处理 |
|---|---|---|
| 大 schema 自动分组、任意稀有模式的完整发现 | 完整证据超过上下文预算或有限分层仍漏检 | 明确停止或报告未知范围；本次 P02/P03 先实现有限分层和候选回退 |
| embedding 候选召回 | 词法召回不足 | 保留未决；当前不加载额外模型 |
| 更复杂的公式、别名绑定和否定范围 | 输入实际包含这些语法 | 原文留存，未知语法未决 |
| 同表多类型条件分派 | 一表内混合多类定义 | 基本类型保守建模，不为填满五类根而分类 |
| 跨来源稳定身份、融合和增量 | 路线2的局部发现已经有效 | 进入路线3，不改写快照身份 |

## 5. 下一阶段：字段统计与关联发现

这组任务来自 2026-09-23 的设计更新，**全部待实现**。不改写上文已经验证的代码状态，详细契约见[字段统计设计](FIELD_PROFILING_DESIGN.md)。

| 顺序 | 对应 US | 具体工作 | 验收条件 |
|---|---|---|---|
| P01 统计口径 | 14 | `profiling.py`；空值策略、32 列以内分组聚合、统计范围与精确性；保留原值 | NULL/空白/前导零案例；空列与空表分母明确；近似基数不能宣布唯一 |
| P02 频次与样本 | 15 | 按候选计算精确频次；固定内容哈希、高频、稀有结构、反例配额；最多一次补样 | 固定输入与重排输入的样本内容可比较；重复来源不合并；未选组/超限范围可查 |
| P03 字段召回 | 16 | `discovery.py`；元数据/原值倒排/结构/FTS 候选并集；角色未知回退 | 无关 ID 仅成为候选；2% 显式引用不能因全列低包含率消失；没有候选与预算未处理分开 |
| P04 精确验证 | 17 | 条件内外统计、目标键计数、作用域复合键、规范化碰撞、多义和缺目标 | 同时报告行与不同键分母；目标重复不被 DISTINCT 隐藏；缺作用域不强行选目标 |
| P05 语义与计划 | 18 | 组装候选证据包，复用 AgentScope 结构化调用；语义依据、条件、转换校验后编译 | 统计重叠不能直接成为业务关系；模型提出的新候选重新验证；继承全局调用预算 |
| P06 回归与对照 | 14—18 | A0/A1/A2/A3 实验；候选召回、关系准确率、未处理范围、代价分项报告 | 固定原基线；已知答案与留出分开；百万行扫描/执行覆盖和模型调用独立计数 |

依赖：P01 → P02/P03 → P04 → P05 → P06。先用中性合成夹具，再用实际输入验证；不要为演示预置业务表、根类型或引用规则。频次和候选统计由 SQL/程序完成，不逐行交给 LLM。

配置草案为 [profiling.design.yaml](../../route2/config/profiling.design.yaml)。完成迁移时须增加配置版本校验，防止现有 CLI 忽略未支持选项却让使用者误以为已启用。外部 IND 引擎和 LSH Ensemble 留作按需对照，不提前加入运行依赖。

本节 P01—P06 目前仅完成[统计口径的合成 SQL 验证](../../route2/design/field_association/README.md)：16 项数值检查通过。它不代表 P01—P06 已实现，也不改变此前原型回归测试的验证范围。

## 6. 实际命令

```bash
uv run ontology-r2 build --config config/runtime.mock.yaml --profile E2F --output runs/my-e2f
uv run ontology-r2 build --config config/runtime.mock.yaml --profile E2F --llm-mode agentscope --output runs/my-llm-e2f
uv run pytest -q
uv run ontology-r2 visualize --run runs/my-e2f
```

`.env`、模拟夹具、企业 MCP 替换方式和规模命令见 [IMPLEMENTED.md](IMPLEMENTED.md)。旧版 `python -m r2 ...` 接口草案不作为运行入口。
