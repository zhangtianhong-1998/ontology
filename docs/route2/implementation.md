# 路线2：实现清单与后续任务

本文中的代码、配置路径及命令均以仓库的 `route2/` 目录为基准。

路线2已具备独立可运行入口，不依赖路线1先完成改造。上游 RIGOR 保留原样；本轮根据源码补齐直接映射、逐表增量、core 上下文、Judge 修正和合并前校验，使用内部 YAML 契约。

## 1. 当前原型的交付范围

| 任务 | 对应 US | 当前实现 | 验证与范围 |
|---|---|---|---|
| T01 导入与元数据图 | 01、06 | `storage.py`、`pipeline.py` | 三类 YAML、CSV、23 表无外键、复合键、跨 schema 同名表；快照内记录身份 |
| T02 引用与条件 | 02、09 | `models.py`、`relations.py` | 作用域匹配、三值条件、JSON 键路径、空引用、目标歧义；不把候选回写为外键 |
| T03 公式绑定 | 03 | `formula_symbols`、`formula_occurrences` | 有限 AST 语法、函数/常数排除、原文位置、多目标依赖；未知语法未决 |
| T04 成员与规则 | 04、09 | `members` 提取器 | 显式允许列表与观察成员分开；保留作用域和 selector；不解释任意自然语言否定 |
| T05 文本关联 | 05、06 | SQLite FTS、`text_target`、`semantic_cards.py` | 既有关系计划执行时做有界文本候选；新增实例组包对去重定义卡做中文 2/3 字 n-gram BM25，并可对上限内卡片使用本地 embedding。两条路径均只是候选召回 |
| T06 外部模型与生成 | 08、09 | `external.py`、`pipeline.py` | RDF/CDM 局部导入、译词召回、原文支持、内部 ID 保留；不实现完整 OWL 推理 |
| T07 企业检索 | 07、13 | `knowledge.py`、`mock_mcp.py` | 真实 stdio 协议、有界查询/摘要、空/无关/冲突/错误分开；仅引用过的有效 claim 进入生成上下文 |
| T08 批处理与可追溯性 | 06、10 | DuckDB、SQLite、YAML 分片 | 记录上限、语义组上限和总调用预算；未处理范围、可见轨迹、哈希、缓存命中可查 |
| T09 无业务例子的输入 | 11 | `demo.py` 的 unrelated 场景 | 无公式、维度和记录关系时正常结束，不生成示例业务类型 |
| T10 模型接入 | 12 | `llm.py`、`.env.example` | AgentScope 2.0.8 SDK 已调用本地兼容 HTTP 服务及配置的火山引擎 `deepseek-v4-flash` 端点；合成输入上的调用只验证接入与结构化响应，不验证业务质量 |
| T12 增量构建 | 19—21 | `incremental.py` | 全字段映射、声明依赖顺序、core 复用、Judge 修正复验及失败回滚 |
| T13 原生 ReAct | 22—23 | `knowledge.py` | AgentScope 2.0.8 `Agent/ReActConfig`；自主工具调用、二次查询及知识用途/出处检查 |
| T14 结果浏览 | 24 | `visualization.py`、`viewer.html` | 本地页面、有限预览、关系证据、业务概念、记录对齐、未决项和构建步骤 |
| T11 运行与资源 | 全部 | `cli.py`、`scripts/benchmark.py` | E2L/O/K/F 来源开关；每次新目录；本路线独立源码和模型副本，无 SAND 依赖 |

原型代码保持普通函数、小型模型和固定提取器枚举，增加一个 ReAct 检索 Agent 和本地 HTML 浏览页；不增加图数据库服务或通用多 Agent 调度平台。

## 2. 验收案例对应

- C01—C05：已测试元数据覆盖、复合键/命名空间、无关数据不连边、条件引用及公式绑定。
- C06—C09：已测试显式成员列表与观察值区分、不同条件不合并、JSON 局部引用；文本相似但业务口径不同的真实判别质量仍需真实模型验证。
- C10—C12：已测试空/无关/冲突/错误文档、固定读工具范围、根模型校验及条件保留。模拟响应验证的是控制流程，不能据此认定任意提示注入都能被模型正确识别。
- C15：已提供规模脚本并测试导入与执行上限；百万完整语义抽取另列，不能把 `partial` 当全量完成。
- C16：固定输入与模拟响应的重复运行、共享缓存回放已验证；记录 ID 限定来源快照。跨快照排序变化和在线模型重复运行没有被这项测试覆盖。
- C17：已验证完全没有示例业务结构的中性输入。
- C13/C14：属于路线3的身份融合和增量维护，本次不实现。

具体结果和运行目录见 [验证报告](VALIDATION_REPORT.md)。

## 3. 仍需实际环境验证

1. 在同一冻结输入、模型和预算下运行 E2L、E2O、E2K、E2F，分别观察候选遗漏、未决和成本；本轮合成输入已经做有界火山引擎调用，但未形成这些配置的公平对照，不能作为模型质量分数。
2. 获得企业 MCP 契约后，适配真实 search/fetch 参数、权限、文档定位与范围字段；当前只是本地 stdio 服务。
3. 获得真实数据后，评估表角色、跨记录关联、单位/口径冲突、根类型区分和候选召回。现有业务举例不进入真实输入假设。

以上需要尚未提供的环境或数据，代码不会用模拟结果冒充完成。

## 4. 按实验结果决定的增强项

| 项目 | 触发条件 | 首版处理 |
|---|---|---|
| 大 schema 自动分组、任意稀有模式的完整发现 | 完整证据超过上下文预算或有限分层仍漏检 | 明确停止或报告未知范围；本次 P02/P03 先实现有限分层和候选回退 |
| CSV 定义记录的 embedding 候选召回 | 词法召回不足，且语义卡数量与本地内存可控 | 已有上限内的可选卡片批量编码与精确余弦候选；Windows 离线依赖、缓存与真实 Gold 召回仍待验证 |
| 更复杂的公式、别名绑定和否定范围 | 输入实际包含这些语法 | 原文留存，未知语法未决 |
| 同表多类型条件分派 | 一表内混合多类定义 | 基本类型保守建模，不为填满五类根而分类 |
| 跨来源稳定身份、融合和增量 | 路线2的局部发现已经有效 | 进入路线3，不改写快照身份 |

## 5.1 关联 Agent 与实例组包：首版与待验收项

需求见 [US29—US36](requirements.md)，完整契约与对照实验见[实例组包设计](INSTANCE_BUNDLE_DESIGN.md)。实验编号为 IB0—IB4，与旧字段发现实验 A0—A3 分开。下表区分已编码的首版路径与尚未通过的设计验收；合成工程回归不代替真实数据质量验证。

| 顺序 | 状态 | 已做及待做 | 验收重点 |
| --- | --- | --- | --- |
| P07 | 首版已编码；数据机基线未跑 | 全输入扫描、定义/引用/不确定卡、磁盘去重与配额遗漏报告；规则/配置/锚点/日志卡只作上下文，常见凭据值不进语义卡；非常规列和 JSON 深层内容待测 | 在同一快照固定代码/配置/模型/提示词，保留失败/跳过/未判定，测入卡召回 |
| P08 | 首版已编码；真实 Agent 路径未验 | 可选 ReAct 只读工具、受限规则、单列恒等匹配全量复验及反例；显式别名、复合键、多态目标与变换待做 | `checked_technical` 不能自动升级为业务关系；缺留出支持只称观察子集 |
| P09 | 首版已编码 | 中文 2/3 字 n-gram FTS5/BM25 与精确名称通道；Gold Recall@K 未测 | 两字词、别名、短编码与未入索引长尾分别计数 |
| P10 | 可选原型 | 上限内定义卡批量编码、精确余弦与词法候选 RRF；无持久向量索引，Windows 离线包未验 | 在 Windows 3.14.7 CPU 完成离线安装与 top-k 烟测，再比较 IB2/IB3 |
| P11 | 首版已编码 | 概念与关联两类包、有限正例/反例和覆盖；有限名额跨根类型/表分散，纯数字碰撞后置；同根定义表或锚点/定义表共享定义键时优先作为概念对齐线索；尚缺高频/稀有/条件分支保底及组包时完整请求字节预留 | 证据不足时未决，不能将相似边当已验证连接 |
| P12 | 首版已编码 | 概念对象/记录对齐与关系计划分开校验，可选 Judge；关系需要同一正例双方非关联键原文，`exact` 遇截断语义字段拒绝，新概念至少一条 `exact` 定义来源；尚缺多轮组调度、完整口径冲突与缓存失效回归 | 每条对齐可追溯原字段；失败不改 core；新快照重验 |
| P13 | 未完成 | IB0—IB4 分层结果、五级候选召回、语义质量、未决及成本对照 | 未入卡/未选种子计入端到端漏召回；检索提升不替代业务关系正确率 |

下一步在固定数据、模型与预算上做 P07—P13 对照，先量出词法遗漏，再判断向量贡献。单个 Agent 只负责少数关联规则探索；组包调度、扫描与规则复验由程序完成，没有逐行 Agent。

配置草案为 [profiling.design.yaml](../../route2/config/profiling.design.yaml)。运行版使用 `discovery` 字段控制候选和验证预算；草案中其余未接入参数不能当作已启用。后续需增加配置版本校验，防止无声忽略选项。外部 IND 引擎和 LSH Ensemble 留作按需对照。

首版代码已由合成数据测试覆盖；有界火山引擎运行、全量合成数据程序扫描与未测项记在[水果经营实验记录](EXPERIMENT_FRUIT.md)。[先前的统计口径 SQL 验证](../../route2/design/field_association/README.md)仍是独立设计证据。真实数据的候选召回率与语义正确率均未验证。

## 6. 实际命令

```bash
uv run ontology-r2 build --config config/runtime.mock.yaml --profile E2F --output runs/my-e2f
uv run ontology-r2 build --config config/runtime.mock.yaml --profile E2F --llm-mode agentscope --output runs/my-llm-e2f
uv run pytest -q
uv run ontology-r2 visualize --run runs/my-e2f
```

`.env`、模拟夹具、企业 MCP 替换方式和规模命令见 [IMPLEMENTED.md](IMPLEMENTED.md)。旧版 `python -m r2 ...` 接口草案不作为运行入口。
