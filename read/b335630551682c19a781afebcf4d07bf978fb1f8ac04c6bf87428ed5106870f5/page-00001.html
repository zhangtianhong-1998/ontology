13## 1. 已确定的需求
14
15- 输入来自 GaussDB 导出文件。当前有 23 张表，包含表列、约束、外键三个目录的 YAML；路线2、3另读 CSV。23 是当前规模，不写死在代码中。
16- 路线1只处理元数据；1A 不用外部本体和企业文档，1B 按配置接入外部本体，两者都不接企业 MCP。
17- 内部一级对象为 `GeneralObject`、`Measure`、`Metric`、`Dimension`、`Term`。一级对象关系为 `contains`、`depends_on`、`related_to`、`points_to`；一级数据关系为 `has`。其他对象类型和关系类型必须从这些根派生。
18- 本体及其语义产物使用 YAML。OWL 仅可能出现在外部模型导入端，不作为内部模型和校验的前提。
19- 重点发现实际输入中的记录关联及条件。指标、度量引用、地区限制、公式等仅是举例，不代表真实数据中存在相应表、字段或规则。
20- 不设计人工确认、人工修订和发布审批流程。自动流程可以输出未决项，不允许用猜测补齐结果。
21- 百万条记录由程序批处理；LLM 用于有限的语义判断、计划生成和疑难关联。
22
23已知信息足以设计输入契约、可选提取器和实验流程。具体对象与关系模式必须由输入发现；不硬编码示例表名，不要求真实数据具备公式、维度或条件规则，也不为填满五类根对象而生成实例。

49## 4. 原型代码要求
50
51**代码必须简洁，以跑通和验证算法为优先。** 每个原型以 Python 环境、CLI 和本地文件运行；优先普通函数、少量类型定义和清晰的数据流。路线预留独立入口，复用必要的模型、输入适配和校验代码。路线3的可选 SAND/GRAMS 插件按依赖版本隔离环境。
52
53不为本原型建设 Web 管理台、微服务、消息队列、通用多 Agent 平台或图数据库集群。元数据图使用本地节点表、边表和邻接索引；批量数据使用 DuckDB。可选的关联 Agent 通过有界只读工具提出规则，程序核验后才能进入组包；企业 MCP 检索另有有轮数上限的 Agent 循环，两者均可关闭。
54
55验收要分别回答：格式是否正确、证据是否可追溯、关系是否正确、处理范围多大、成本多少。LLM Judge 通过、YAML 能加载、图连通或节点增加，都不能替代语义质量评价。
