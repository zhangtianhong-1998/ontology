# 从数据构建本体：建议方案与验证设计

本文件是基于文献的工程建议，**不是已经实现或验证成功的系统**。它回答“针对已有不足，具体怎么补；补了之后，怎样知道是否有效”。文献缩写与链接见[综合报告](01_本体自动构建_综合研究报告.md)和[扩展报告](03_扩展研究与开源实践.md)。

## 1. 明确自动化目标及输入条件

建议将目标定为：从限定领域的资料中生成**带证据、可修订的本体候选及数据映射**，逐步验证后发布。开始前需固定领域边界、核心业务问题、允许的概念粒度、目标表达语言和可接受的人工工作量。领域判断用于确定要求，不必逐条人工批准所有简单事实。[设计建议；依据L18的需求与能力问题流程、L02的任务边界]

至少拆成三条实验轨道：

| 轨道 | 允许输入 | 禁止暗中补入 | 主要测试 |
|---|---|---|---|
| A：数据驱动发现 | 原始记录或自然文本，必要读取结构 | Gold概念名、Gold关系、目标本体定义 | 能否发现新概念与结构 |
| B：有元数据辅助的发现 | A + DDL/注释/SQL/公开给定业务说明 | 未声明的专家定义、测试答案 | 额外证据能否改善解释与映射 |
| C：已有本体下的扩展/映射 | B + 明确给出的种子或目标本体 | 把完整目标本体当种子再声称从零发现 | 能否正确补充、对齐和填充 |

三条轨道可共用测试问题，但成绩不能在省略输入条件后直接排名。已有类型列表显著改变了问题，这在LLMs4OL、OLLM和SPIRES的设置中可直接看到。[L17 §2；L02 §3；E08 §3]

## 2. 建议的阶段、输出和检查

### 阶段1：固定数据与来源身份

对文档、表、字段、查询和转换脚本生成稳定ID；保存内容散列、提取时间、来源版本、可见范围。PDF保留物理页码和段落，表保留列路径及记录范围，SQL保留表达式和作用域。增量运行先比较输入变化，避免每次产生新的无关联概念。[工程建议；增量思想参考E01/E05，映射参考S01]

**输出**：来源清单和物理元数据图。此时的外键、引用、JOIN和血缘边只记录技术事实，不自动命名为业务关系。

**验证**：抽样回放来源；同一输入重复导入身份不变；SQL同名列在不同作用域不会混为一列；数据删除能找到依赖它的候选。后两项为本方案验收要求，现有18篇未直接证明它们已被解决。

### 阶段2：生成可定位的候选事实

文本可分别采用开放抽取和给定模式抽取；结构化数据采用确定性解析与数据剖析。保留原话与模型归纳的区分，并记录否定、时间、单位、条件、主体/客体角色。输出一个主张时，必须能定位其支持材料；找不到支持材料的内容保留为待查假设。[方法参照E04/E08；具体数据结构为本方案设计]

每条候选建议保存如下信息；这只是结构示例，不是实际抽取结果：

```json
{
  "claim_id": "claim:example-001",
  "subject": "concept:order",
  "predicate": "has_purchaser",
  "object": "concept:customer",
  "claim_kind": "relation_candidate",
  "scope": {"business_process": "retail", "valid_from": null},
  "evidence": [
    {"source_id": "doc:example", "locator": "page:3,paragraph:2", "relation": "supports"}
  ],
  "counterevidence": [],
  "proposed_by": {"method": "extractor", "version": "frozen-version"},
  "checks": {"source_support": "pending", "logic": "not_run", "data": "not_run"},
  "status": "candidate"
}
```

**验证**：人工盲审主张是否由引用材料支持；同时测漏抽，防止通过大量弃答获得漂亮精度。模型置信度单独存储，只有经留出集校准后才可解释为经验概率。

### 阶段3：分开处理身份、概念及名称

建议同时维护实例ID、概念ID、名称和别名。候选名称接近时，先判别它们属于同一实例、同一概念、上下位概念、角色还是只是相关。定义、已有ID和范围优先于字符串相似度；匹配器不能直接把近邻合并成`sameAs`或`equivalentClass`。[设计建议；归一化收益与误合并问题参照E04/E05/E07]

**验证**：构造同名异义、异名同义、角色/实体、类/实例四类困难样例，分别测误合并和漏合并；保留“无法确定”，不强制每个候选匹配。记录合并前后边和引用如何变化，以便撤销。

### 阶段4：生成关系和层级，再检查全局结构

候选召回可采用词面、嵌入、上下文、规则和跨簇补充的并集，再交给关系判定器。候选中明确区分直接父子关系与祖先关系。对事件建模时保留参与者角色、时间及发生条件，而非把同一实体的所有时间状态压成一条静态边。[设计建议；L01/L17关系任务差异，L11候选召回不足，E06事件表示]

**验证顺序**：先测候选真边召回，再固定候选测分类；最后检查全图方向、循环、重复、冗余、无依据的根节点及异常多父结构。多父不自动视为错误，需根据目标本体允许的语义判定。[L02图合并与去环；工程建议]

若真实关系全集为G且|G|>0、候选集合为C、预测集合P满足P⊆C，则最终召回

`|P∩G| / |G| ≤ |C∩G| / |G|`。

这是集合包含关系，不是实验估计。实际评测的Gold可能不完整，此时测得的是相对于已标注关系的召回，不能直接当作真实全集召回。这个上界解释为什么只改善候选内部的分类器仍可能无效；ELLMO的GO候选召回0.0975提供了实际例子。[L11 PDF p10表10；该表其他F1存在原文疑点，见逐篇报告]

### 阶段5：分别产生统计规律、逻辑定义和数据约束

可以并行使用：QSE提形状，AMIE提关系规则，DL-Learner/Ontolearn提类表达式，FCA提蕴含及反例问题；LLM负责解释候选、寻找文档证据和建议修订。[E03/E14/E15/E16]

**不能统一成一个布尔“正确”。** 对每条候选记录：样本支持数、反例数、覆盖范围、完整性假设、是否有规范定义、是否允许例外。对稳定定义、公理、统计关系、数据质量要求分别保存。训练数据符合只能证明其在该快照上的情况。

**验证**：新时间段、不同业务分区和人工构造困难反例分别测试；若候选来自数据，至少用未参与生成的数据检查。阈值由开发集选择，不能按测试结果不断调整后仍报告同一测试分数。[实验设计建议；不完整性与置信度依据E14/E15]

### 阶段6：三种检查分开记录

| 检查 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 来源支持检查 | 引用材料支持该主张及范围 | 来源本身必定正确、普遍成立 |
| OWL逻辑检查 | 所选逻辑下的一致性、可满足性与蕴含 | 商业定义真实、所有信息齐全 |
| SHACL/数据检查 | 当前图符合所指定形状 | 形状必然合理、现实不存在例外 |

检查记录还需注明工具支持的语言范围与运行状态。超时、未支持的表达式、未覆盖的规则必须记为“检查未完成”或“未覆盖”，不能当作检查通过。[工程验收建议]

再加**能力问题测试**：根据固定业务问题检查完整答案和来源。查询可解析、可执行、有结果、答案正确，应当是四个不同字段。[S03；L18的查询验证差异]

### 阶段7：发布、更新、撤回

发布包包含本体、别名/定义、数据映射、来源索引、未决问题及测试结果。对概念合并、拆分、更名、关系方向调整和公理删除使用显式变更记录。证据被删除或更正时，重新检查受影响主张和测试，不必重建全部无关内容。[工程建议；E01/E05增量思路、L18后向兼容缺口]

**验证**：预先设计更名、删除、相反新证据、同名新概念和粒度变化五类事件；测受影响候选的识别、错误撤回、无关概念保留，以及历史版本可回放。现有文献的增量合并结果不能替代这组变更测试。

## 3. 实验怎么设计才有说服力

### 3.1 至少保留四种基线

1. **简单基线**：字符串/词元规则与确定性数据库映射。SBU的OBI结果提示这类基线可能相当有竞争力。[L05表4]
2. **直接LLM基线**：同模型、相同输入和输出格式的一次抽取/判定，用于检查复杂流程是否带来增益。
3. **检索或受约束基线**：明确提供同一份种子/候选信息，公平比较是否增加来源和约束更有效。
4. **拟议组合方法**：分阶段证据、候选处理、规则检查及必要人工修订。

人工方式作为时间/质量对照时，应使用同一需求、统一产物要求和独立盲审；专家和初学者分别分层，随机分配任务或采用交叉设计，避免再次出现40h/16h不能归因的问题。[L18；实验建议]

### 3.2 逐个检验组件，而不只比较完整系统

| 待检验假设 | 对照 | 预期同时记录 |
|---|---|---|
| 增加定义能改善语义判定 | 有/无定义，固定候选与模型 | 精度、召回、错误定义敏感性 |
| 候选过滤能减少成本而不严重漏边 | 不过滤/词面/嵌入/并集 | 候选召回、总F1、调用量 |
| 聚类提高效率 | 有/无聚类，固定判定器 | 跨簇漏边、误合并、时间 |
| 集成比单模型值得使用 | 最佳单模型/等成本重复/集成 | 精度、成本、投票与审议贡献 |
| 微调能泛化 | 冻结/微调，同模型同数据 | 同域、新域、新概念成绩 |
| 形式检查减少实质错误 | 有/无检查，保留被拒候选 | 拒错/误拒、修订量、最终语义质量 |
| 来源与反例机制减少人工负担 | 有/无证据展示，随机审阅 | 达到同等质量的总工时 |

这些对照针对IRIS多因素混杂、DREAM缺等成本对照、silp缺聚类消融，以及SEMA/Alexbek跨域和配置差异而提出；并不预设每个组件都会有效。[L08/L09/L13/L14/L15]

### 3.3 固定数据，避免把答案泄漏进输入

- 先固定原始资料、Gold、提示、模型版本、候选生成、参数和评价脚本，再运行比较。记录异常及失败请求，不只保留成功样例。
- 将测试集按来源文档/对象/时间/概念划分；分别测试已见类型、新类型和新领域。若不同切分共享定义或祖先边，明确披露。
- 用本体生成的合成文本只能作为单独的受控测试；自然资料应另外保留，包含遗漏、别名、否定、时间变化和互相矛盾的说明。[L02切分；L17合成数据]
- 已有KG缺少的边可能是未知，不应全部视为真实负例。用于严格精度评价的困难负例需有人工或明确规范依据；未标注的合理新知识进入独立审查。[E04不完整参考集；E15完整性假设]
- 如让LLM评审，冻结评审提示和模型，另设人工盲审校准集。生成器与评审器不同不等于评价已独立可靠。

### 3.4 Gold不仅是一份“标准本体”

建议为测试样本保存概念定义、允许别名、身份边界、关系方向、必要/可选公理、来源依据、可接受替代建模和不可回答项。某些领域允许多个合理建模方式，不应只因与参考文件不同就判错；但替代方式必须满足相同能力问题和语义约束。[实验设计建议；L02匹配指标、L17字符串规则、L18能力问题]

人工标注至少记录分歧和裁决过程。首轮可以抽取每类错误100–200项、固定20–30个能力问题作为**预算可调整的试点建议**；这些数字不是文献证明的充分样本量。正式样本量应根据事件稀少程度、预期差值与置信区间需要确定，尤其不能用少量容易样本代替罕见错误评测。

### 3.5 怎样决定方案有效

以共同质量目标比较成本，或以共同成本预算比较质量，避免一边增加模型调用与专家劳动，一边只比较准确率。

建议预注册三类验收条件：

- **质量**：最终语义精度、覆盖、关键错误率达到预先约定要求；不同领域单列，不让大领域掩盖小领域失败。
- **工程**：能回放来源、撤销合并和处理变更；推理/约束检查的失败有明确定位。
- **效率**：包含人工审阅、纠错和回归后，达到同等质量所需总工时或费用降低。

对高风险身份合并和硬公理，不建议用一个未经校准的模型分数自动发布。具体阈值需要试点数据决定；本报告不杜撰“90%即可上线”等通用数值。若完整方案只提高局部F1，却降低覆盖或增加总工时，结论应写成局部改进，而不是整体有效。

## 4. 本次研究可以直接支撑的下一步

先选择一个边界清楚的小领域，在三条轨道中挑适用的一条；建立少量可判定的能力问题和留出集，再比较简单基线与分阶段方案。优先检查候选漏检、身份误合并、关系方向、时间/条件丢失四类错误，因为后续图与公理步骤会依赖它们。

如果上述基础质量仍低，先修输入与证据覆盖；如果候选充分而判定错误多，再考虑领域适配；如果局部判断好但整体图差，优先检查全局约束和合并。这个诊断顺序由本地候选召回、跨域失效与图结构实验共同支持，实际收益仍需按照本文件的对照设计验证。[L02/L09/L11/L12/L13]
